## 一个看起来很成功的记忆系统，可能只是抽到了一手好牌

设想一个大语言模型（LLM）驾驶代理：它先在 8 个驾驶回合中积累经验，之后遇到并线场景时检索相似经历，再决定保持速度、变道还是减速。实验显示，无记忆代理有 51% 的回合不碰撞；加上经验记忆后，这个数字升到 66% 或 67%。很自然的故事是：**过去的经验帮助了驾驶。**

但这个故事至少有三个漏洞。

第一，换一组 8 个热身回合会怎样？如果记忆池恰好包含“早减速就能避险”的好案例，结果可能很好；若池里留下了激进或不适配的经验，同一个系统可能反而更差。第二，加入记忆也加入了更多文字。模型可能并没有读懂经验，只是因为提示更长、语气更保守，开始更早减速。第三，只用“不碰撞”评分会奖励一个笨办法：永远减速甚至原地拖延，也能看起来很安全。

这篇论文的真正研究对象因此不是“哪种记忆结构最先进”，而是更基础的问题：

> **在固定规划器和评测协议后，经验池抽样、提示词组成、记忆表示和基线实现分别贡献了多少？所谓记忆增益能否跨经验池、跨对照、跨指标成立？**

作者最初也提出了自己的复杂方法——时序图记忆 TG-Mem（Temporal-Graph Memory）。但论文的价值恰恰在于，作者让更严格的控制实验推翻了对自家方法最有利的解释：在这个测试台上，经验池和提示组成比“记忆里存了什么结构”更能决定结果。

## 先用一个例子理解整套设计

以下是一个贴合论文机制的教学示例，数字不是原文实验。

假设驾驶代理要处理同一个并线场景，基础提示有 200 token。我们比较四种输入：

1. **无记忆**：只看当前场景，共 200 token。
2. **经验记忆**：检索一个过去回合，提示增至 1,000 token。
3. **等长无关填充**：不放驾驶经验，只加 800 token 明确可忽略的无关文本，总长度同样约 1,000 token。
4. **一句谨慎指令**：只加“遇到不确定时优先减速”之类的短句。

若第 2 组优于第 1 组，我们仍不能说经验有用，因为内容和长度同时变了。若第 3 组也一样好，说明“多出一段上下文”或这段上下文引起的行为偏移可能足以解释增益。若第 4 组最好，而代理几乎每步都减速，那么“不碰撞率”测到的可能只是谨慎程度，不是记忆推理。

接着，把经验记忆中的 8 个热身回合换成十组互不重叠的池 A–J。若只有池 A 提升，其余池都下降，那么池 A 的漂亮数字不是方法的稳定效果，而是一次幸运抽样。本文就是沿着这两条轴——**池抽样**与**提示组成**——层层拆解结果。

## 作者怎样把问题变成可检验的实验

### 固定什么，改变什么，观察什么

所有方法共享场景编码器、规划提示骨架、离散动作空间和闭环仿真协议。主要实验用 HighwayEnv 1.11，在 1 Hz 决策频率下运行；决定性比较使用 gpt-4o-mini、温度 0、固定随机种子和严格 JSON 输出。作者还探索 Llama-3.3-70B-Instruct 与 Mistral-Small-3.2-24B，但把小样本结果明确标成探索性证据。

每个“方法 × 场景 × 模型”组合先在热身池上学习，再冻结记忆，在互不重叠的评测种子上只检索、不继续学习。无记忆、原始历史和填充对照不需要热身。这样，主要变化被限制在记忆系统这一个“处理包”中：存储表示、检索键、检索内容与注入格式。

这里仍需谨慎：这个处理包内部有多个同时变化的成分。因此，主实验能估计“采用整套记忆设计”的效果，却不能仅凭总体差异把效果归因于某一个组件。作者随后用消融、2×2 设计与诊断任务继续拆分。

### 被比较的记忆与对照

| 方法 | 它代表什么 | 每步给规划器什么 |
|---|---|---|
| No-Memory | 零记忆基线 | 当前场景 |
| DiLu port | 平面文本经验检索 | 用当前帧文本做 embedding，余弦检索相似经验 |
| Grid port | RESPOND 风格的单帧网格模式 | 5×3 自车中心风险网格及匹配经验 |
| TG-Mem | 作者的时序图记忆 | 结构与时间联合匹配的图式回合 |
| Consolidated rulebook | 无逐步检索的经验蒸馏 | 从整个热身池压缩出的至多 8 条规则 |
| Flat K-step history | 直接历史基线 | 最近 K−1 个原始帧，不存储、不检索 |
| Padding / fillers | 提示组成对照 | 与记忆近似等长但不提供驾驶建议的文本 |
| Caution line | 行为倾向对照 | 仅 15 token 左右的谨慎驾驶指令 |

DiLu 与 grid 都是作者在统一测试台上的重实现，不是原系统直接运行。作者对移植版本做了审计：DiLu 的早期残缺实现曾把其安全率压低近一半；grid port 又未通过三个复现审计中的两个，只复现了约 51% 的决策与 49% 的网格单元。因此，涉及它们的结论只能写成“本文审计后的 port 在该测试台上如何”，不能外推成原论文系统的优劣。这是本文很重要的诚实边界。

### TG-Mem 到底怎样工作

TG-Mem 把一个最近 K 步的驾驶回合编码为小型有类型时序图。节点包括自车、其他车辆、车道和风险；空间边描述 ahead_of、left_of、merging_into 等关系，时间边连接同一实体从时刻 $t$ 到 $t+1$ 的状态。执行动作和结果作为回合元数据保存。

检索时，当前窗口也被编码成查询图 $q$。每个历史回合 $e$ 的分数是：

$$
s(q,e)=\alpha s_{\text{struct}}(q,e)+\beta s_{\text{temp}}(q,e),\qquad \alpha+\beta=1.
$$

直觉上，$s_{\text{struct}}$ 问“现在有哪些类型的对象和空间关系与过去相同”，$s_{\text{temp}}$ 问“对象随时间变化的模式是否相同”。二者都用有类型元素的多重集 Jaccard 重叠计算；$eta$ 越大，时间关系权重越高。取分数最高的若干回合，序列化成“场景 → 动作 → 后果”文本，追加到统一规划提示中。发生碰撞时，系统再让 LLM 反思何种动作可以避免碰撞，并把纠正后的回合写回记忆。

这个设计看似能表达比平面文本更丰富的关系，但有一个值得留意的实现边界：抽取器看不到真正执行的动作，所谓因果边是模型推断，而不是由干预或日志直接识别的因果关系。论文如实披露了这一点。

## 评测坐标系：四类场景、两类指标、三层统计

论文不只在一个常规并线任务上报总分，而是把场景分成四类：

- `merge-v0`：多步接近、让行与并线，主确认性实验每方法 100 个共享评测种子。
- `stopgo-v0`：前车稳定或走走停停，专门诊断检索键是否能区分历史模式，每条件 20 个，属于探索性实验。
- `telegraph-v0`：前车先两次短促减速后恢复，再突然重刹；当前单帧无法区分危险与正常类型，必须利用历史信号。每类 20 个，并在运行 LLM 前用脚本 oracle 证明任务可解。
- `highd-cutin-v0`：从 highD 数据集中重构 54 个高风险切入事件的初始几何，14 个热身、40 个评测。它不是原轨迹回放，之后由 IDM 控制非自车，因此只保留了真实事件的初始风险形状。

主安全指标是不碰撞率。但作者担心它奖励“过分谨慎”，于是回放每条动作序列，记录平均速度、完成时间、超时率，并预注册 Safe-and-Swift：必须不碰撞、不超时，且平均速度至少达到无记忆均值的 90%。这让“安全”与“完成任务”同时进入构念。

同一场景的各方法使用相同种子，因此比较采用配对的精确 McNemar 检验，而不是把两组独立对待；同一检验族用 Holm 校正。热身池层面则先用模型无关的符号检验，数一数十个池中有几个正效应，再对池级效应做非参数 bootstrap。作者把 $n\leq20$ 的单元明确标为探索性，确认性结论主要依赖并线的 $n=100$ 和诊断的 $n=40$。

## 结果一：池 A 给出“记忆有效”，换九个池后结论翻转

先看最容易被拿来写摘要的 Table 2。固定 gpt-4o-mini、merge-v0、共享 100 个评测种子与热身池 A：

| 方法 | 不碰撞率 | Safe-and-Swift | 平均速度 m/s | 每决策 prompt token |
|---|---:|---:|---:|---:|
| No-Memory | 0.510 | 0.40 | 24.2 | 210 |
| DiLu port | 0.670 | 0.67 | 25.6 | 274 |
| TG-Mem | 0.660 | 0.45 | 23.2 | 1,038 |
| Flat K-step history | 0.750 | 0.31 | 22.5 | 527 |
| Irrelevant padding | **0.800** | 0.29 | 22.3 | 1,037 |

在池 A 下，TG-Mem 相对无记忆的配对差异经 Holm 校正后仍显著（24 个种子由失败转成功、9 个反向，$p=0.041$）；DiLu 的 0.67 则是边缘证据（$p=0.073$）。TG-Mem 与 DiLu 几乎不可区分（17 对 16 个不一致种子，$p=1.0$），但 TG-Mem 的每决策 prompt token 约是 DiLu 的四倍。仅看这张表，最多能说“池 A 下两种记忆有一个局部增益，复杂图结构未显示优势”。

Figure 3 才是全篇最关键的图。横向列出十个互不重叠的 8 回合热身池 A–J，纵向是不碰撞率；虚线是没有热身池的 No-Memory 0.51，色带是四种等 token 填充的范围，点线是谨慎策略的上限。读图时应先看每种记忆有多少个点高于 0.51，而不是只找最高点。

结果是：池 A 恰好是 DiLu 与 TG-Mem 十次抽样中最好的池。其余九池中，DiLu 只有 0.11–0.37，TG-Mem 只有 0.08–0.48。每种记忆都仅在 10 个池中的 1 个超过无记忆，在另外 5 个池显著更差；精确符号检验给出 $p=0.011$。十池平均效应均约为 −0.20：DiLu 的 bootstrap 区间是 [−0.29, −0.10]，TG-Mem 是 [−0.30, −0.09]。

把热身预算从 8 回合增到 40 回合确实缩小了不同池之间的波动，但没有带来稳定收益：A40 与 B40 的 DiLu 分别为 0.54 和 0.60，均未在 Holm 校正后优于无记忆。这里的结论不是“更多数据一定无效”，而是**在本文的 40 回合预算与方法下，增加预算只减少了抽签波动，没有建立正平均效应。**

Takeaway：单一热身池比较回答的是“这个池是否适配这个评测”，不是“从热身分布随机抽一池时，记忆通常是否有帮助”。

## 结果二：等 token 的无关文字比所有检索记忆都高

记忆方法不仅改变内容，也把每步提示从 210 token 拉到 274–1,038 token。作者构造了 1,037 token 的 irrelevant-padding：它没有存储、检索或反思，内容被明确说明与驾驶无关且可以忽略，仅匹配 TG-Mem 的总提示足迹。

在 merge-v0 上，这个对照达到 0.80，高于无记忆（$p=2\times10^{-6}$）、TG-Mem（$p=0.029$）和 DiLu（$p=0.024$）。四种 filler 的点估计为 0.59–0.80，没有一种被任何检索记忆超过；弱 filler 与记忆之间仍处于统计噪声范围，所以不能说它们严格等价，但 arbitrary filler 之间 0.21 的跨度已经大于记忆相对无记忆的 0.15 “增益”。

这说明提示组成是强混杂因素，却还没有识别具体机制。为了进一步定位，作者做了 disclaimer × domain 的预注册析因实验：同样的无关内容是否明确写“可安全忽略”，以及内容来自哪个领域。去掉 disclaimer 在一个内容家族只下降 0.05，在另一个下降 0.24（$p=3\times10^{-4}$），说明“无关文字”的效应也不是单纯 token 数，位置、语气与内容类型存在交互。

最强反例是一句约 15 token 的谨慎指令：“防御性驾驶；不确定时优先 SLOWER。”它让不碰撞率达到 0.98，与 always-SLOWER 脚本策略和最好 rulebook 持平，并高于所有约 1,000 token 的 filler 和所有记忆。模型有 99.9% 的动作都选择 SLOWER。长 padding 也把前五步 SLOWER 比例从 33% 推到 45%。

因此作者把观察到的主导行为称为“caution dial”：提示组成改变了代理的谨慎倾向。这个名字描述了早期减速比例与安全率的共同变化，不等于已经识别了模型内部机制；论文也明确承认长度、位置、风格和指令显著性尚未完全交叉控制。

Takeaway：等长随机文本不是“无意义的弱基线”，而是区分语义价值与提示组成效应所必需的负对照；同时，等长仍不等于等机制，需要进一步拆分位置、语气与内容。

## 结果三：只看碰撞会把“永远减速”误认成智能

三个非 LLM 脚本策略给不碰撞率定标：always-IDLE 为 0，十行反应式 gap-keeper 为 0.40，always-SLOWER 为 0.98。后者说明碰撞指标几乎可以被无脑保守策略刷满。

rulebook 把每个热身池压成至多 8 条固定规则，不做逐决策检索。它在最初五个池 A–E 中稳定达到 0.97–0.98，看似解决了检索放大池噪声的问题。作者于是预注册了一个可证伪条件：在五个新池 F–J 中，只要有一个低于最强 filler，就推翻“池免疫”。新结果分别为 0.98、0.33、0.03、0.78、0.23；三个池低于所有 filler 和无记忆。

更关键的是，十个池的 early-SLOWER 比例与不碰撞率几乎同序（Spearman $\rho=0.89$）。高分 rulebook 把前五步中 78%–100% 的动作变成 SLOWER，运行点与 always-SLOWER 一样：约 21.0 m/s、16.9 步。加入任务进度后，这些最好看的 rulebook 单元 Safe-and-Swift 全是 0。

这不是说谨慎行为没有价值，而是测量问题：若目标真是“只要不碰撞即可”，0.98 是有效结果；若目标是安全完成并线，超时与低速必须计价。论文通过并列报告不碰撞率与 SaS，揭示了指标对代理策略的诱导。

还有一个常被忽略的交互：把 DiLu 与 padding 简单叠加，并没有得到“两种有效成分之和”，反而在池 A、B、D 上降到 0.26–0.30，低于单独 DiLu 与单独 filler。这提醒我们，不同上下文块可能竞争注意力或改变指令解释，不能假定可加性。

Takeaway：必须先用简单策略证书问“指标是否可被一个与目标无关的策略刷高”，再谈方法提升；安全指标若不同时计入进度，会把保守偏置包装成规划能力。

## 结果四：复杂表示没有显示稳定作用，真正起作用的成分随任务变化

作者设计 `stopgo-v0`，原本想给时序记忆创造优势：前车在出生时完全相同，一类保持匀速，一类之后走走停停，似乎需要历史才能识别。

探索性结果却相反：在停走回合上，经过筛选的平面 DiLu 达到 0.95，无记忆 0.45，TG-Mem 只有 0.10，单帧 grid 为 0。事后分析发现，一旦制动开始，当前帧的闭合速度已经泄露类型，而 DiLu 恰好用当前帧文本作精确检索键；TG-Mem 的粗粒度类型袋反而匹配不准。这个诊断实际上测到了 key precision，而没有证明“时间键必要”。

作者用两个变体做了漂亮的双重分离：

- 在 merge-v0 池 A 上，去掉经验筛选使 DiLu 从 0.67 降到 0.49，而把语义键换成词法键仍有 0.65：这里筛选重要，键精度不重要。
- 在 stopgo 的三个热身划分上，未筛选但语义精确的键得到 1.00/1.00/0.70；筛选过但粗糙的词法键只有 0/0/0.15：这里键精度重要，筛选不重要。

这意味着“哪一组件起作用”依赖任务机制。完整 key type × injection format 的 2×2 设计还发现，紧凑注入在各热身划分下都稳定有害；键类型效应则随池翻转。即使机制归因也会继承热身池抽样的不稳定。

`telegraph-v0` 进一步修掉单帧泄露：危险前车在第 4 和第 6 步各做一次“减速后恢复”的预告，第 8 步后重刹；出生间距有抖动，临近重刹时的单帧状态在危险与正常类型间不可区分。成功必须既不碰撞又达到进度目标，所以一直慢行无法通过。类型感知脚本 oracle 在危险与正常两类均为 1.00，证明任务可解。

所有被测 LLM 设计都没有通过预注册标准：各方法在两个池的危险回合上均为 0/20 成功。失败形式却很有信息：池 A 的 DiLu 在正常回合全成功、危险回合全碰撞，呈激进倾向；换池 B 后，它从激进整体翻成胆怯，正常回合从 1.00 降到 0，危险回合由全碰撞变为全超时。原始 K 步历史包含两次预告，危险回合 20/20 不碰撞，却 0/20 达到进度；正常回合也仅 9/20 成功。换言之，信息已经在上下文里，但规划器只学会了“一直谨慎”，没有学会“识别危险后减速，再恢复进度”。

这个结果把“检索不到”和“拿到信息也不会用”区分开来。TG-Mem 的时序键理论上可区分类型，但没有转化成正确控制。论文提出的下一步 oracle-retrieval arm 正是把正确证据直接交给规划器，进一步估计检索与利用瓶颈。

Takeaway：更丰富的表示能编码信号，不等于规划器会利用信号；必须设计历史必要、单帧不可解且简单保守策略不能过关的诊断任务。

## 其他边界实验与消融

在 40 个 highD 风险切入初始状态重构上，无记忆已经有 0.875 不碰撞率，TG-Mem、DiLu 与 grid 分别为 0.775、0.800、0.825，均不显著（$p\ge0.37$）。这里基线接近饱和，所以既没有支持记忆，也不是很强的反证；更不能把“真实数据初始化”说成真实闭环交通轨迹。

在 merge-v0、池 A、$n=40$ 的 TG-Mem 消融中，完整模型为 0.70：去掉反思降到 0.475（配对 $p=0.004$），把窗口缩成单帧降到 0.40（$p=0.017$），去掉时间边为 0.55（$p=0.070$）。可以说反思与多帧窗口在这个池里有帮助；时间边这一核心新组件至多只有边缘证据，而且消融仅在幸运池 A 上做，无法证明跨池必要性。

模型与决策频率也是明确的异质性边界。Llama-3.3-70B 在并线上几乎饱和，所有方法至少 90%，记忆差异难以显现。探索性的频率扫描中，DiLu 相对无记忆的差值从 0.5 Hz 的 +0.40，变成 1 Hz 的 +0.16，再到 3 Hz 的 −0.30；效应符号就在文献惯用的 1 Hz 附近穿零。因此，“记忆是否有效”也依赖代理多久做一次决定。

## 证据审查：这篇论文证明了什么

### 有较强证据支持的结论

1. **单池结果不能代表平均热身池效果。** 两种检索记忆都只在 10 个池中的 1 个胜过无记忆，十池平均效应为负；这是符号检验、池级 bootstrap 与分层模型方向一致的结果。
2. **本文测试的检索记忆没有超过等 token 填充。** 最强 padding 显著高于 DiLu 与 TG-Mem；这足以否定“池 A 的提升必须来自经验语义”这一解释。
3. **不碰撞率受到强烈的谨慎倾向影响。** always-SLOWER 和 15-token 谨慎指令都达 0.98，rulebook 的安全率与 early-SLOWER 高相关；加入进度要求后 rulebook 领先消失。
4. **复杂时序图表示没有表现出稳健优势。** TG-Mem 未跨划分优于平面记忆，时间边消融只有池 A 下的边缘证据，所有方法又都未通过 oracle 可解的历史必要诊断。
5. **基线移植质量能反转结论。** 残缺 DiLu port 曾制造 TG-Mem 的虚假胜利，grid port 的复现审计失败又限制了对原系统的任何推断。

### 论文没有证明的内容

- 没有证明所有代理记忆都无效。结论限定在 HighwayEnv、离散元动作、1 Hz、8–40 回合热身与以 gpt-4o-mini 为主的弱规划器环境。
- 没有证明 filler 的内部作用机制。早期 SLOWER 偏移是可观察行为签名，不等于长度、位置或注意力机制已被分别识别。
- 没有做 filler 与记忆的等效性检验。“记忆没有超过 filler”与“两者严格等效”不是一回事。
- 没有证明原版 DiLu 或 RESPOND 的系统优劣；实验对象是作者的审计移植，尤其 grid port 未通过保真审计。
- 没有证明真实道路闭环驾驶中的外部有效性。highD 只提供初始几何，后续交通并非原始轨迹。
- 十个池足以较有把握判断平均效应的符号，但不足以精确估计效应大小；作者也明确把幅度称为粗略估计。

## 真正应该记住什么

- “记忆带来提升”至少要拆成：抽到了什么经验、注入了什么文字、加入了多少 token、代理行为倾向如何变化。
- 经验池不是固定常量，而是研究总体中的随机因素；若部署时池会变化，评测就应跨池估计分布或平均效应。
- 等长无关填充是必要控制，但不是终点；还需交叉长度、位置、语气、领域与免责声明。
- 一个好诊断任务必须先由 oracle 证明可解，并堵住当前帧泄露与“永远谨慎”这类替代路径。
- 复杂表示的表达能力、检索命中和规划器利用是三件不同的事；后两者失败时，表示再丰富也不会转成闭环收益。
- 代理评测的单位常常是“完整产品/端到端 port”，不是论文里一个抽象方法名。基线实现审计应与结果表同等重要。

## 对当前研究的直接启发

当前 causal-review 实验正在比较处理相关上下文（P/I）与随机代码（R），并计划固定总输入长度、共享同仓外部 donor、比较 `method-added + R`、`all-R` 与 `P replaces R`。本文提供的不是结论迁移，而是一套可直接强化该设计的实验纪律。

### 1. 把 donor / pool 从“素材”升级为随机因素

不要只为每个 case 抽一次随机代码。对同一 case、模型、基础上下文与 token 预算，重采样多个独立 donor pool，报告：

- 每个 pool 下处理相对 all-R 的配对效应；
- 正效应 pool 的比例与符号检验；
- 跨 pool 平均效应及 bootstrap 区间；
- pool 是否改变失败倾向，而不只是改变最终准确率。

这样估计的对象才是“从预定 donor 分布抽取随机上下文时，语义上下文平均是否更有用”，而不是“这次恰好抽到的 R 是否较弱”。

### 2. 固定总长度之外，再做内容 × 剂量的析因分解

本文证明了“token-matched”仍可能混入语气、位置与领域。当前设计可以把每个预算层级写成更清晰的 2×k 结构：内容类型（P/I vs R）× 剂量（0.5/1/2/3/5×），并固定：插入位置、块数、分隔符、注释密度、编程语言、repo 来源与去重规则。超过 P 池容量后只增加 R 时，应把横轴标成**总外加 token 剂量**，另报 P 的实际占比；不能把 5× 解释成 5× P treatment。

### 3. 加入“短指令”与“格式占位”控制

若 plausible context 带有函数名、注释、调用关系标记或“相关代码”措辞，模型可能仅被提示成“更谨慎/更愿意检查依赖”。可以加入两类低成本对照：

- 长度几乎不变的短指令，直接要求“修改前检查跨函数依赖”；
- 保留相同标题、分隔符与 metadata，但正文替换成等长 R 的格式占位组。

如果短指令能复制大部分效果，结论应转向行为诱导；若只有真实 P/I 在多个 donor pool 上稳定领先，才更接近语义内容效应。

### 4. 不只看最终 pass/fail，还要给代理“倾向”定价

驾驶论文用 early-SLOWER 揭示了谨慎偏置。代码代理也可寻找对应的中介或副作用指标：读取文件数、跨文件跳转数、搜索/工具调用数、修改文件数、补丁大小、测试运行次数、拒答/超时、无关编辑与 token 成本。一个上下文处理若只让代理更保守、搜索更多，却没有提高正确修复或降低副作用，就不应被解释为更好的因果定位。

### 5. 增加 oracle-context × planner-use 诊断

当前 55/67 gold 覆盖不全使检索、覆盖与利用混在一起。可在覆盖完整的 20 个 case 上增加 oracle arm：直接给出 gold 相关对象，但不附带多余 plausible 内容。将结果分成：

1. oracle 仍失败：规划器不会利用正确上下文，或修复本身超出能力；
2. oracle 成功、P 失败：检索/候选选择是主要瓶颈；
3. P 与 oracle 都成功、R 失败：才是较清晰的语义上下文收益证据。

这与论文的 telegraph 诊断完全同构：信息是否存在、是否被检索到、是否被正确用于决策必须分开。

### 6. 模型别名漂移必须像 baseline port 一样审计

研究记录已经确认同一 API 名在 10 月中旬实际模型发生变化。本文的 M4 告诉我们，实现或底座质量能静默反转结论。后续分析应把真实 provider/model 版本、日期、请求哈希与 prompt 快照纳入实验单元；新旧模型分层报告，不能把它们合并成同一 treatment 重复。每次大规模运行前，用少量固定 canary case 验证输出分布与工具行为是否漂移。

最后，本文最值得带走的不是“随机文本竟然有效”这句奇闻，而是一条更严谨的研究原则：**当上下文干预同时改变样本、长度、格式与代理倾向时，先设计能推翻自己最喜欢解释的对照，再谈机制。**
