## 先把场景说清楚：谁卡住了，下一步可以买什么

这里的“卡住”不是一个会自主求助的完整产品，也不是代理已经反复修了十轮仍没成功。论文先冻结一个非常具体的失败时刻：给定任务 $x$，编码代理已经产出一份未通过隐藏测试的代码或仓库补丁 $y$，并留下此前看到的上下文 $h$。三者合起来是检查点 $s=(x,y,h)$。研究者接管这个失败状态，只允许同一个修复模型再改一次。

在最后一次修改前，它可以得到三类资源：

| 资源 | 论文中的含义 | 一个直观例子 |
|---|---|---|
| 计算 $C$ | 多一次只分析、不运行工具也不改代码的规划调用 | “先再想 2,048 token，写出诊断和修复计划” |
| 信息 $I$ | 与任务有关、但不读取当前失败产物的外部知识 | “正确行为应该是什么；应修改哪些位置” |
| 反馈 $F$ | 运行当前失败产物后得到的观察 | “公开测试输入、期望输出和当前输出” |

三者不是三个要比较的“系统”。它们是加在同一个失败状态、同一个修复模型和同一个最终提示协议上的三种**干预通道**。模型也不是第四种资源，而是把资源转化成修复的“技术”。这一区分很重要：论文不是宣布某个代理框架赢了，而是在问同一模型、同一失败补丁、同一次最终修改中，额外预算花在哪类资源上最值。

这个问题比“多给 token 是否有用”更精确。多给 1,000 token，既可能让模型自己多想一会儿，也可能装进一段准确规格，或装进一份测试失败日志。总 token 相同，作用却可能完全不同。论文的核心发现正是：**token 不是可随意兑换的统一货币；对强模型，更多空想几乎没有价值，任务规格仍然有价值。**

## 一个八格小实验，理解整篇论文

假设一个函数要“返回输入列表中第二大的不同元素”，代理却把重复的最大值当成第二大值。我们冻结这份失败代码，复制成八份：

| 格子 | 得到的资源 | 最终修改前看到什么 |
|---|---|---|
| 000 | 无 | 原任务、失败代码、原上下文 |
| 100 | $C$ | 再做一次分析并写计划 |
| 010 | $I$ | 明确“distinct、重复最大值只算一次”的规格 |
| 001 | $F$ | 一个公开测试及其期望/实际输出 |
| 110 | $C+I$ | 规格，再让模型做计划 |
| 101 | $C+F$ | 测试报告，再做计划 |
| 011 | $I+F$ | 同时给规格和测试报告 |
| 111 | $C+I+F$ | 三者都给 |

八份最后都进入同一个修复调用：相同模型、模板、最大输出长度，且不能再用工具。然后在**没有泄露给模型的隐藏测试**上评分。

如果只比较 000 与 010，我们只能说“规格单独给时是否有帮助”。却不知道已经给了测试反馈后，规格还能增加多少；也不知道规划与反馈是在互补，还是重复解决同一批失败。八格全跑，才可以比较 $I$ 在另外两项资源的四种背景下各自带来的增量，并把四个增量平均。这个平均边际贡献就是信息的 Banzhaf value，也是本文的平均主效应。

因此 BRA（Banzhaf Resource Attribution）不是一个新修复代理，而是一套**冻结状态、完整析因、反事实分叉的测量框架**。

## 为什么这篇工作值得读

它是 2026 年 10 月提交的预印本，并在 Long-Context Foundation Models workshop 展示。这个渠道说明工作很新，但不能把预印本当成已被主会充分验证的定论。真正价值有三点。

第一，它把“代理需要什么”从端到端相关性问题变成了固定失败状态上的干预问题。真实轨迹里，资源、状态和下一次编辑同时变化；某次测试调用之后成功，可能只是因为代理又获得了一次编辑机会。BRA 把最终编辑次数锁死，令格子之间只差被分配的资源。

第二，它认真区分了**有用信息**和“看起来像上下文的东西”。仓库里检索五段 BM25 代码几乎没有价值；告诉模型正确行为和位置的审计规格却有稳定效果。论文没有用后者粉饰成可部署检索器，而明确称它为 instrument：用来回答“如果信息到位，会怎样”，而不是宣称系统已经能获得它。

第三，它不只问平均效果，还问交互、模型能力、成本和代理自己的选择。结果中最有讽刺意味的一点是：三个模型在 95%–100% 的失败点都主动选择测试反馈，但反馈恰恰是三类资源中平均价值最低的一类，它们的选择甚至不如均匀随机。

## BRA 到底怎样跑

### 第一步：构造并冻结失败检查点

函数级数据来自 MBPP+ 与 HumanEval+。作者让 Qwen3-4B 用 2,048 token 快速作答，保留所有隐藏扩展测试未全过的第一次尝试，共 194 个失败：131 个 MBPP+、63 个 HumanEval+，基础平均通过比例为 0.32。

仓库级数据来自 SWE-bench Verified。作者在分层抽取的 250 个任务上运行文本版 mini-SWE-agent（Qwen3-14B、最多 75 步），保留 126 个未解决且补丁不退化的检查点：62 个 Django、21 个 SymPy，另 43 个来自八个仓库。57 个补丁会让测试运行崩坏，69 个能运行但目标测试失败。另有 30 个由 DeepSeek-V3.2 代理自己失败的 native-failure 检查点，用来检查结果是否只是“修别的模型的错”造成。

### 第二步：把资源通道做成可分配干预

**计算 $C$** 是同一个模型额外做一次 analysis-only 调用。主实验预算 2,048 token，剂量曲线从 256 到 4,096。它能读任务、当前产物以及本格子已有的 $I/F$ 包，只能返回文字诊断和计划，不能执行、检索或编辑。计划被追加到最终修复上下文。

**信息 $I$** 必须依赖任务，但不能读取当前失败产物，这样才不会混入“针对这次错误的反馈”。函数级主信息是从参考解写出的输入输出契约与边界情况。仓库级设置了四级梯子：

1. retrieval：用 issue 文本对基准提交的仓库做 BM25，取五段代码；
2. location：从参考补丁机械抽取被改文件和包围函数；
3. behaviour：根据参考修复描述根因与所需行为，但禁止写文件、函数、变量名；
4. specification：location 与 behaviour 合并。

其中 location、behaviour 与 specification 使用了参考补丁，是诊断上限，不是现实系统可直接拥有的输入。书写包还经过自动审计，检查是否泄露参考解行、隐藏测试字面量、标识符等。函数实验另有等长中性文本 placebo，用来排除“只是多了一段文字”。

**反馈 $F$** 只来自执行当前产物，不会自动修改代码。函数主实验的 F3 报告最多五个失败输入及期望输出，剂量从仅给通过数的 F1，到再给实际输出的 F4。公开测试与最终评分的 EvalPlus 扩展测试分离。仓库中若至少有两个 FAIL_TO_PASS 测试，就只观察其中一个而在其余测试上评分；否则只报结果计数。这个 split-test 设计防止反馈直接包含最后的考题答案。

### 第三步：所有格子只做一次相同修订

对每个检查点、每个修复模型，八个格子都使用相同最终调用协议。函数最终输出上限 2,048 token；仓库修复输出是最多 4,096 token 的 search/replace edits，并用 SWE-bench 官方 harness 评分。Qwen3-14B 和 DeepSeek-V3.2 在函数级每格跑五次，其余每格三次；仓库级每格三次。

作者评测六个模型：Qwen3-4B、14B、32B 构成同家族规模梯子，另有 DeepSeek-V3.2、GPT-5.6 与 Claude Sonnet 4.5。所有模型关闭 hidden reasoning，温度 0.7。函数固定状态面板让六个模型修相同 194 个错误；matched-difficulty 只保留六者在空格子都表现很差的 24 个点；native-failure 面板则让失败来源随模型变化。这三种视角分别回答“转化资源的能力”“同难度下能力差异”和“模型自己的典型失败”。

### 第四步：从八个格子算主效应与交互

令 $q_{cif}$ 表示某一格子的期望隐藏测试通过比例。计算资源的平均主效应为：

$$
\mathrm{AME}_C=\frac{1}{4}\sum_{i,f\in\{0,1\}}(q_{1if}-q_{0if}).
$$

直觉是：在“无/有信息 × 无/有反馈”的四个背景里分别加一次计算，然后取平均。$I$ 和 $F$ 同理。这正好等于该资源在三玩家合作博弈中的 Banzhaf value。

计算—信息的交互为：

$$
\Gamma_{CI}=\frac{1}{2}\sum_f(q_{11f}-q_{10f}-q_{01f}+q_{00f}).
$$

若它为正，规划让信息更有用，二者互补；若为负，二者大致修好了同一批错误，后加入者的收益变小，即替代。作者还计算三阶交互、Shapley value、单独充分性、从完整组合中拿掉某资源的条件必要性，并把七个对比量组成“瓶颈指纹”。

不确定性以检查点为重采样单位做 2,000 次 bootstrap，而不是把每次随机 rollout 当独立样本；三组两两交互用 Holm 校正。这一点避免了伪重复。

## 实验问题与证据

### Q1：失败时真正缺的是哪类资源？

在 194 个共同函数失败上，信息对六个模型的平均主效应为 0.064–0.136，全部 $p<0.001$，五个模型中它是最大资源。公开测试反馈只有 0.007–0.033；计算对弱模型居中，对强模型接近零。

两个控制排除了容易的反驳。等长中性 placebo 对 Qwen3-14B 与 DeepSeek-V3.2 的作用分别是 −0.016、−0.002，均与零不可区分；真实规格相对 placebo 却提高 0.195、0.126。所以作用来自内容，不只是多 token。反馈也不是剂量太小：在 DeepSeek 最难的 40 个检查点上，从仅给通过数升级到给完整实际输出，反馈单独格子只从 0.362 升到 0.402；仅 256 token 的计划已经到 0.489。

结论应精确写成：**在本文的一次修订协议里，关于正确行为的规格是平均最紧缺的资源；公开测试反馈平均较弱。**这不等于迭代代理中测试不重要，因为反馈还可能控制停止、引导下一轮工具使用，而这些被单次设计有意排除了。

### Q2：模型越强，瓶颈怎样移动？

Figure 2 最清楚。沿 Qwen3-4B、14B、32B、DeepSeek-V3.2、GPT-5.6、Sonnet 4.5，计算效应依次为 0.131、0.110、0.101、0.053、0.010、0.007；最后两个置信区间覆盖零。信息的下降小得多，仍保持 0.064–0.136，并在五个模型中排名第一。信息占三项主效应之和的比例从弱模型的 40% 上升到强模型的 83%，计算从 49% 降到 8%。

强模型空格子通过率已到约 0.81，可能有天花板。作者于是只看六个模型都低于 0.5 的 24 个共同难点：信息效应反而增至 0.12–0.25，对所有模型显著；GPT-5.6 与 Sonnet 的计算仍只有约 0.03且不显著。再看同家族 Qwen 规模梯子，计算效应也随规模从 0.131 降到 0.101，减少了“只是厂商不同”的解释。

这不是“强模型不需要推理”，而是：**在已失败的相同状态上，再加一轮显式计划的边际价值随能力下降；缺失的外部任务知识仍然无法只靠更强计算稳定重建。**

### Q3：资源是互补，还是重复劳动？

作者预注册的假设是互补：规划会让信息和反馈更有生产力。数据把这个假设推翻。六模型 × 三对资源 × 全样本/远离天花板样本共 36 个交互中，21 个经 Holm 校正后显著为负，没有一个显著为正。

例如 Qwen 梯子的计算—反馈交互是 −0.090、−0.056、−0.045，说明规划与测试报告常救回相同失败。远离天花板后，计算—信息交互落在 −0.10 到 −0.14，除 Qwen3-4B 外都显著；所以负交互不只是评分上限压出来的。

需要注意，平均负交互不等于每个检查点都严格次模。只有 25%–78% 的单点响应面满足精确次模条件，28%–81% 满足单调性，随机修订噪声也会造成局部反常。可靠结论是总体上收益递减，第一项资源的选择尤其关键，而非“永远只给一种资源”。

### Q4：仓库里“检索到代码”是否等于“拿到信息”？

这是与当前研究最直接的一组结果。126 个 SWE-bench Verified 失败比函数题难得多，空格子通过比例仅 0.026–0.423。把五段 BM25 代码当信息时，四个模型的信息主效应只有 −0.002 到 0.009，反馈 −0.006 到 0.009，没有一项显著；更多上下文没有转成修复。

把同一批检查点中的 $I=1$ 格子换成审计过的 oracle specification，图景完全改变：

| 修复模型 | BM25 检索代码的 $I$ 效应 | oracle 规格的 $I$ 效应 |
|---|---:|---:|
| Qwen3-14B | 0.009 | 0.048 |
| DeepSeek-V3.2 | 0.007 | 0.083 |
| GPT-5.6 | 0.005 | 0.103 |
| Claude Sonnet 4.5 | −0.002 | 0.088 |

四个规格效应都显著（$p\leq0.002$）；完整资源相对空格子的增益也由检索时的 0.01–0.04 变为 0.07–0.12。在 DeepSeek 自己造成的 30 个失败上，retrieval 为 −0.004，specification 为 0.079，方向一致。

Figure 3 的信息梯子进一步回答“到底缺什么”：只告诉修改位置的效应为 −0.03 到 +0.02，单独几乎无用；只告诉根因与正确行为为 0.013–0.047，仅达到完整规格效应的 17%–57%；位置与行为一起给，效应才到 0.048–0.103。两半合并的收益还大于各自收益之和，四模型的互补量为 0.034–0.115，其中三个置信区间排除零。

因此标题式结论“retrieval is not information”要翻译得克制：**论文中的稀疏 BM25 代码片段没有交付修复所需的“在哪里改 + 应该变成什么行为”这组联合证据。**它没有证明所有检索器、所有仓库上下文无效；oracle 规格又使用参考补丁，不能直接当可部署方法的成绩。

### Q5：模型会给自己选择正确资源吗？

作者把空格子上下文交给模型，让它在“再规划一次、获得所需行为规格、查看执行报告、什么都不要”中选一个，选项顺序还会打乱。然后不重新跑一个不同实验，而是在同一检查点已经测得的响应面上给这项选择计分。

Qwen3-14B、DeepSeek-V3.2 和 Sonnet 4.5 在函数和仓库两类任务上有 95%–100% 的检查点选择反馈。GPT-5.6 在函数级有 49% 选择信息，但仓库级仍有 71% 选择反馈。

这种“反馈执念”代价很高：函数级三个执念模型只拿到逐检查点 oracle 可得增益的 10%–27%，比永远选信息少 0.078–0.101，也比均匀随机少 0.029–0.064（均 $p<0.001$）。仓库级永远选信息也在四模型上都高于模型自选，三者显著。但 28%–45% 的检查点上，最佳单项资源并不是总体最优项，所以固定“总选信息”仍不是终点；真正目标是学习状态依赖的分配器。

### Q6：能否只按 token 或美元做预算分配？

同一检查点八个格子的总 token 成本，通常不如三个资源指示变量更能预测结果；仓库级甚至比只用检查点均值更差。这直接否定“加多少 token 就应得到多少收益”的标量模型。

每增加 1,000 token，函数级信息带来 0.54–1.25 的效用增益，是计算的四倍到二十多倍；仓库级规格信息为 0.11–0.31。反馈自身增益小，但包很短，所以按 token 的回报率不一定很差。按当前边际收益/成本贪心选择，在函数级达到最优可负担组合收益的 0.80–0.99，仓库级达到 0.89–0.97。不过这是已知完整响应面的事后经验比率，不是一个已经训练好、在线可用的路由器。

## 证据审查：哪里很扎实，哪里必须降调

### 较扎实的部分

1. **完整 2³ 设计比单项消融多识别了交互。**八个组合全部观测，Banzhaf 主效应和三阶以内交互可精确从格子均值计算，不靠“无交互”假设。
2. **冻结失败状态和最终修订协议处理了轨迹混杂。**只有最终调用能编辑；计算无工具，信息不读失败产物，反馈不检索；隐藏测试、参考解与最终评分输入有 canary 审计。
3. **多个控制指向“内容而非长度”。**等长 placebo 近零，真实规格显著；反馈和计算剂量增加也没有改变主排序。
4. **能力、任务家族与失败来源都有分层检查。**共同状态、共同难度、Qwen 同家族梯子和 DeepSeek native failures 的方向基本一致。
5. **负结果没有被藏掉。**BM25 retrieval、反馈、强模型额外规划，以及预注册的互补假设均以负结果出现。

### 必须保留的边界

1. **只测一次最终修订。**真实代理里反馈还负责循环控制、停止判断和生成后续工具动作；论文为了识别资源而主动舍弃了这部分外部效度。
2. **oracle 信息来自参考修复。**它证明的是信息供给瓶颈，不是一个系统已经能自动生成等质规格；把 0.103 写成检索系统收益会失真。
3. **固定状态总体来自特定生成器。**194 个函数错误都由 Qwen3-4B 首答产生，126 个仓库错误主要来自 Qwen3-14B mini-SWE-agent；虽然有 30 个 DeepSeek native failures，失败分布仍不代表所有代理。
4. **模型结果具有时间版本性。**闭源模型名、API 行为和价格会变；论文报告的是运行时版本，不应外推成永久模型属性。
5. **检查点级响应仍有随机噪声。**每格仅 3–5 次 rollout；平均效应的 bootstrap 合理，但单点 oracle 资源和分配 regret 会含较大测量误差。
6. **信息通道在自然语义上并不完全正交。**失败测试也是信息，额外规划也可能重建规格。作者实现的是“来源与注入路径的正交干预”，不是认知内容完全互斥。
7. **最新预印本尚需独立复现。**数据、冻结检查点与格子输出若能完整发布会显著帮助验证，但当前阅读不能替代复现实验。

## 一句话抓住全文

这篇论文最重要的不是“信息比计算更好”，而是：

> **要判断卡住的代理缺什么，必须在同一个失败状态上分别供应资源并观察所有组合；否则轨迹中的更多思考、额外知识、测试反馈和再次编辑会纠缠在一起。**

在本文的一次修订环境里，弱模型还会从额外规划获益，强模型的规划边际收益接近零；两者都持续受益于准确规格。公开测试反馈和 BM25 代码片段平均很弱，三类资源总体呈替代。更有挑战的是，模型自己并不知道这一点，经常把下一笔预算投给最不值的反馈。

## 对当前研究的直接启发

当前研究刚完成 15 例、两模型的 plausible/irrelevant（P/I）追加：Qwen 的 P−I F1 为正，DeepSeek 接近零；DeepSeek 上 P 同时减少漏报又增加额外定位，F1 把两种行为折叠了；此外 I 供给不足、剂量饱和、函数类型与候选数未严格匹配。BRA 恰好给出下一步如何把这些现象变成更可识别问题。

### 1. 不再只问 P 是否优于 I，而问每类资源的响应面

当前 P/I 比较主要估计两个上下文包的差。可以把一次定位或修复失败冻结为检查点，定义更贴近任务的三通道：

- $C$：同模型额外一次只分析、不读取新代码的规划；
- $I$：当前 P 或严格匹配的同仓无关 donor；
- $F$：静态检查、测试、编译或 reviewer critique 的失败报告。

先在 10–20 个审计过的 case 上跑完整 $2^3$，将最终输出协议锁死。这样可以回答 P 是单独充分，还是只在反馈存在时有用；也可以检验额外 planning 是否只是重建 P 所含信息。无需一开始扩到全量，完整小面板比大规模单轴剂量更能发现交互。

### 2. 把“P”拆成 location 与 behaviour，不要把代码存在当信息到位

本文仓库结果几乎是当前问题的镜像：知道文件/函数位置单独无效，知道行为只拿到部分收益，两者结合才完整。建议为 gold 覆盖的 case 构造四级梯子：

1. 当前检索到的 plausible 代码；
2. 只给 oracle node / function location；
3. 只给不含标识符的正确行为或依赖关系；
4. location + behaviour。

如果 1 无效而 4 有效，结论是检索没有交付足够证据；如果 4 仍无效，才更像模型利用/修复能力瓶颈。当前“55/67 gold 覆盖”也应进入分层：有 oracle 覆盖与无覆盖不能混成同一处理含义。

### 3. 将漏掉 GT 与过度定位设为两个结局

DeepSeek 上 P 减少 missed GT，却增加 extra predictions。BRA 使用隐藏测试通过比例，但你的任务已有更细的机制指标。建议把每个格子同时报告：

- target recall / 漏掉的 GT 数；
- precision-set success / 额外预测数；
- F1 作为综合量；
- 输出集合大小、token 与工具调用成本。

这样能看到某资源是补足证据，还是只把决策阈值推向“多报几个”。不要让一个 F1 主效应掩盖方向相反的中介路径。

### 4. 用匹配 I 和 placebo 审查内容效应

论文的等长 placebo 很关键。当前 I 不仅 token 不足，还可能在类型、候选数、文件位置和 repo 熟悉度上不匹配。后续 donor 至少按语言、同仓/跨仓、函数/方法、token、候选块数与依赖层级匹配；正文替换时保留完全相同的标题、分隔符和注入位置。再加一个“格式相同、语义中性”的 placebo，区分 P 内容与“出现一个标为相关的代码块”带来的行为诱导。

### 5. 在共同失败与 native failure 两个面板分开比较模型

同一批 case 比较 Qwen 与 DeepSeek，能够看资源转化能力；各模型自己失败的 case，又更贴近其部署总体。两者回答不同问题。建议仿照论文：

- fixed-state：两个模型都在同一冻结输入上定位；
- matched-difficulty：仅保留基础条件下二者都明显失败的 case；
- native-failure：每个模型各自的失败集合。

这能防止“强模型剩下的错误更难”被误写成模型更不吃上下文，也能避免共同 case 的天花板掩盖效应。

### 6. 不要让代理自报需求替代真实干预

可以问模型“下一步想看相关代码、测试反馈还是再思考”，但只能把回答当 allocation policy。真正价值必须由相同检查点上的干预结果计分。模型可能非常确信自己需要反馈，却持续选错。若未来要做自适应 context router，应以逐检查点已测响应面或可靠代理标签训练，而不是用模型解释作为真值。

### 7. 对外结论坚持三层证据

- **论文直接证据**：在其一次修订设置中，规格信息平均最有价值，BM25 与公开测试反馈平均很弱。
- **跨研究的可迁移方法**：冻结状态、完整析因、placebo、location/behaviour 梯子、共同难度面板。
- **当前项目待验证假设**：P 的优势是否来自联合提供“在哪里 + 为什么”，以及它是否以更多 extra predictions 为代价。

最值得立即做的并不是把现有 15 例扩成 100 例，而是从覆盖最完整的少数 case 中挑出一批，做 location × behaviour 的小型完整析因，并把漏报与过度定位分开。这样下一轮数据会回答“P 为什么起作用”，而不只是再给一个平均 F1 差值。
