## 正确答案明明在里面，为什么还是答错？

给模型一张写着正确答案的卡片，它能答对；再放进十九张卡片，它却答错了。此时至少有两个解释：材料变长后模型读不过来，或者新增材料太像正确答案的来源，把判断带偏了。只比较“一张”和“二十张”，无法知道是哪一种。

这篇论文把实验再往前推了一步：二十张卡片仍然保留，正确卡片也不变，只把其中十五张看似相关的干扰卡换成较不相关、但同样真实自然的文本。如果成绩恢复，就不能简单地把失败都归咎于“读得太长”。这是全文的核心设计。

### 为什么值得读，以及应当如何看待作者和发表渠道

论文属于检索增强生成（Retrieval-Augmented Generation，RAG）的评估方法研究。RAG 先从材料库找文本，再让模型读这些文本并回答；本文研究后半段的 **reader，即读取给定材料并生成答案的模型**，不研究完整检索系统如何确保把答案找来。它的价值主要是一个容易迁移的实验对照，而非新模型架构。

第一作者是 **Vyzantinos Repantis**。原文将七位作者统一署名为 **Meta Platforms**，没有进一步给研究组名称，也没有星号或文字指定通讯作者，因此不能把第一作者、arXiv 投稿者或末位作者自动写成通讯作者。可核实的相关积累是他此前一作的 [The 99% Success Paradox: When Near-Perfect Retrieval Equals Random Selection](https://arxiv.org/abs/2605.18857)，关注检索成功率与随机基线之间的差距；它标注为 [ICLR 2026 Blog Track](https://iclr-blogposts.github.io/2026/blog/2026/bits-over-random/)，不能写成 ICLR 主会论文。两篇都体现了对评估对照的关注，但背景本身不保证本篇结果可靠。

这是一篇篇幅较短的预印本：实际 PDF 共五页，其中四页正文、一页参考文献，没有附录。不能因作者来自 Meta 就把实验当作充分验证，也不能因它不是软件工程顶会论文而忽视其对照设计。最有用的贡献是：让“竞争文本的内容是什么”和“材料有多少”不再完全绑在一起。

**与当前研究的直接关系。** 当前仓库上下文实验正在分别控制完整 prompt 长度、候选数量和真实处理节点数。本文同时控制片段数与近似输入长度，是很贴近这个缺口的方法先例；但它的片段是问答文本，不是函数节点，长度也不是逐例严格等 token。它适合帮助设计对照，不足以直接证明代码上下文中的 P 比 I 更有害。

## 先用一个例子理解作者到底换了什么

下面是**教学示例，非论文原实验**。

问题是：“某位研究者在哪一年获得某个奖项？”正确材料写了人物、奖项和年份。检索器同时找来十九段文字，可能分别谈同姓人物、同一奖项的其他获奖者，以及该研究者获得的另一种奖励。它们的关键词都很接近问题，但不能支持目标答案。

作者的主要比较不是把十九段全部删掉，而是构造两份材料：

- **Hard 条件**：同一段正确材料，加十九段检索排名靠前的非答案材料。
- **Far 条件**：同一段正确材料，保留四段靠前的非答案材料，再换入十五段排名更靠后、来自同一语料库的真实材料。

两边总共都是二十段，每段使用相同的词数预算；Far 不是空白、乱码，也不是凭空生成的无意义填充。这样，换掉的是检索竞争者的组成，不能说只因为 Far 少读了十五段才恢复。

这里的“hard negative”有一个重要限度：它是 **BM25 排名靠前且没有答案字符串的非 gold 片段**。BM25 是根据查询词与文档词项匹配程度排序的检索方法；高排名只是“可能竞争”的操作性定义，不等于人工证明每一段都会误导模型。Far 也只是较低排名，并不是已经证明语义完全无关。

研究问题因此可以说得很精确：**在正确片段已提供的前提下，把一部分靠前的检索负例换成较远的负例，答案表现是否改善？** 这比“无关上下文会不会害模型”更窄，也更容易做出可信对照。

## 从一条问答到两份可比较的输入

### 1. 先固定正确证据，让实验只研究“读不出”

作者从 **SQuAD 1.1** 抽取抽取式问答：每个问题的答案是原文中的一段连续文本。每条实验输入至少包含一个 gold passage，也就是包含标准答案的原始段落，再把它裁成 gold snippet。

这样做的必要性在于：如果一个条件根本没有正确材料，另一个条件有，那么结果主要反映检索召回差异，而不是读者能否抵抗竞争。本文主动提供正确证据，先隔离后者。

gold snippet 尽可能以答案为中心截取，目标是把答案留在片段里；工件没有提供逐例答案保留验收，因此不能将构造意图当成每题都已验证的保证。干扰片段则按固定词数预算裁剪。输入整理成带编号的片段列表，要求模型只根据给定片段回答。gold-only 基线只有正确片段；其他条件将 gold 位置随机化。[原文 §2](https://arxiv.org/html/2605.27294v1#S2)

**这也引入了一个实验性质上的限定。** 构造者知道标准答案，可以围绕答案裁剪正确片段；真实检索系统一般没有这个能力。因此它是受控阅读试验，不是可直接部署的检索方案。

### 2. 先排除答案泄漏，再区分 Hard 与 Far

BM25 检索负例时排除 gold 原段落。主要匹配实验还对两边所有非 gold 片段做同样的答案过滤：排除包含规范化答案字符串的片段。

为什么这一步不能省？如果 Far 恰好也多了一处答案，模型改善可能来自答案重复出现，而不是竞争减轻。相同过滤规则减少了这一替代解释。但字符串过滤并不证明材料没有答案别名、间接支持或语义等价信息，因此不能扩张成“彻底消除了所有答案泄漏”。

在主实验中，Hard 是 1 gold + 19 hard；Far 是 1 gold + 4 hard + 15 far。**Far 仍含四个 hard negatives**，所以这不是“有竞争”对“零竞争”的全有全无试验，也不是逐个负例的剂量效应估计。

### 3. 为什么用 50 个词，而不是直接指定相同 token？

主实验对两个 reader 都使用每段 50 个词的设置，作者说这样能让 Phi-2 留在 2K 上下文限制内。另有使用 80 个词片段的 Qwen 扫描实验。

“词”和“token”不是同一个计量单位。同样五十个词，名称、数字或拼写不同，分词器产生的 token 数就可能不同；模板和问题本身也占长度。论文表 1 报告的是**平均输入 token**：

- Phi-2：Hard 1487，Far 1496。
- Qwen2.5：Hard 1519，Far 1532。

Far 平均还略长一些。根据表中均值计算，相对 Hard 的差异约为 **0.61%** 和 **0.86%**。这是“平均长度很接近”的证据，**不是每个样本都严格配平的证明**。论文没有给逐例差值的最大值或分布，也没有报告一个逐例容差验收规则。[原文表 1](https://arxiv.org/html/2605.27294v1#S4.T1)

### 4. 模型、检索器和实验单位

reader 是 **Phi-2** 与 **Qwen2.5-1.5B-Instruct**。作者选择两个小型开放模型来展示协议，不声称代表所有 RAG 系统。主要 Hard/Far 匹配对照只使用 BM25；BGE-small 这个稠密向量检索器仅用于 Qwen 的保留率曲线检查。

真正配对的单位是 **question ID**。同一问题的 Hard 和 Far 分数之差用于统计，不应把同一题的多个条件当成彼此独立的新题。正文没有写样本数，但[公开 notebook](https://github.com/repantis-ai/rag-semantic-competition/blob/6e9db091f9ee04cecf3d6e37002d7756f921d55c/notebooks/01_semantic_competition_snippet_controls.ipynb)补足：从 SQuAD validation 的 10,570 个问题里，以 seed=42 抽取 **200 题**；检索语料是去重后的 **2,067 段 context**。各主要设置沿用同一问题抽样逻辑，但干扰片段和排列不完全相同。

## 三种评分为什么会给出不一样的答案

本文同时报告精确匹配（Exact Match，EM）、token F1 和答案包含率（answer inclusion）。它们不是三个可互换的“准确率”。

继续用教学示例，假设标准答案是英文数据中的“1921”，模型经清洗后仍回答“He won in 1921 and received another prize in 1922”：

- **EM** 要求规范化后的整个输出与标准答案匹配。即使答案数字出现了，整段解释也可能使 EM 不通过。
- **token F1** 根据规范化后按空格分开的词项重叠计算，不是按模型 tokenizer 的子词计数；它折中衡量 precision 和 recall。输出包含答案但又混入很多多余内容，会被部分扣分。
- **答案包含率** 只检查某个规范化标准答案是否出现在输出中，因此可能通过；但它不排除输出同时包含别的错误答案或错误解释。

评分实际作用于模型输出经代码清洗、规范化后的文本，原始字符串不一定直接进入评分。三者一起看，可以区分“完全恢复简洁正确答案”和“开始提到正确答案，但输出还不够干净”。这也是为什么不能把本文的 inclusion 改善，直接解读成完整推理可靠性改善。[原文 §2 Metrics](https://arxiv.org/html/2605.27294v1#S2)

## 第一组证据：竞争者越多，成绩怎样下降？

先看一个描述性实验：固定 Qwen reader，逐步增加 hard negatives。BM25 让总片段数 N 依次为 1、20、40、80，也就是 H 为 0、19、39、79；BGE-small 的公开工件与留存结果只有 N=1、20、80，没有 N=40 的实测记录。这组扫描使用 80-word 片段。正文给出的是总体扫描集合，不能据此给 Dense 补一个 H=39 的观测点。

**这里同时改变了长度与负例数量。** 因此它能描绘性能怎样随材料累积而变化，单独不能解释下降究竟由语义竞争还是长度造成。真正用于区分的 Hard/Far 对照在下一节。

### 图 1 应该怎样读

横轴是 hard negatives 数量 H，纵轴不是原始准确率，而是相对 gold-only 的保留率。蓝色圆点实线是 BM25 EM，橙色方点虚线是 BM25 F1，绿色三角点划线是 Dense EM，红色菱形虚线是 Dense F1；横向虚线标出 0.5 的半保留阈值。

四条线都从 1 出发，因为没有负例时各指标除以自身基线等于 1。图中几个关键读法是：

1. 从 H=0 到 19，四条曲线都下降，之后继续下降，而不是突然在某个固定段数完全失效。
2. 到 H=79 时，BM25 的 EM 从 31.0 降至 24.0，F1 从 0.575 降至 0.411。按原文数值计算，分别保留约 77.4% 和 71.5%。
3. Dense 的 EM 从 31.0 降至 23.0，F1 从 0.575 降至 0.405，约保留 74.2% 和 70.4%。两种检索器呈相似下降，Dense 在 H=19 到 79 之间的连线不能当作中间也有实测；图中没有不确定性区间，不能把小幅曲线间差距读成显著排名。
4. 四条曲线都没有碰到 0.5。这意味着在已测范围内，没有看到指标减半，并不意味着完全没有干扰。

作者用一个简洁公式概括曲线：

`R_M(H) = M(H) / M(0)`

其中 M 是所用指标，M(0) 是 gold-only 分数，M(H) 是加入 H 个 hard negatives 后的分数。比值越低，说明相对该基线保留得越少。这个归一化便于看衰减，但不能替代原始分数：一个本来就低的基线，也可能有很高保留率。

作者将第一次降到不高于 0.5 的 H 称为半衰点 K₁/₂。未跨过阈值时，正确报告是 **K₁/₂ > 79，即右删失**：在观察范围右边还没看到事件，而不是猜测它一定发生在某个更大数值。本文并未测出一个实际半衰点，更没有证明曲线服从指数衰减。[原文 §4.1、图 1](https://arxiv.org/html/2605.27294v1#S4.SS1)

这一组的结论是：在这套协议下，增加负例会伴随渐进退化，但“容量阈值”和“纯语义竞争效应”都不能仅凭这张图认定。

## 第二组证据：不减少材料，换掉竞争者能否恢复？

这才是论文最关键的比较。固定同一 reader、同一问题与 gold、总共二十段、50-word 片段规则和答案字符串过滤，只把十五个靠前负例替换为较远负例。

表 1 的行先按模型分组，再比较 Gold、Hard、Far；列是三种评分及平均输入 token。Gold 用来说明只提供正确证据时能做到什么，但它比另两个条件短得多，**不能充当等预算对照**。Hard 与 Far 才是这张表识别竞争因素的主要比较。

| Reader | 条件 | EM（%） | 答案包含率（%） | token F1 | 平均输入 token |
|---|---|---:|---:|---:|---:|
| Phi-2 | Gold | 52.5 | 85.5 | 0.704 | 124 |
| Phi-2 | Hard | 24.5 | 70.0 | 0.459 | 1487 |
| Phi-2 | Far | 30.5 | 77.0 | 0.516 | 1496 |
| Qwen2.5 | Gold | 51.5 | 80.5 | 0.683 | 117 |
| Qwen2.5 | Hard | 22.0 | 58.0 | 0.387 | 1519 |
| Qwen2.5 | Far | 26.5 | 67.0 | 0.455 | 1532 |

以上为原文表 1 的报告值。读这张表要同时看到三个事实：

- 从 Gold 到 Hard，两种模型都明显下降，但这一步把长度和竞争一起增加，不能直接把全部下降都命名为“竞争伤害”。
- 从 Hard 到 Far，平均 token 没有减少，三种指标却都提高。这比单纯删除材料更能支持“材料组成有影响”的解释。
- 恢复是部分的。Phi-2 的 Far EM 30.5 仍远低于 Gold 的 52.5；Qwen Far F1 0.455 也没有回到 Gold 的 0.683。原因可能涉及残留四个 hard、一般长输入负担、具体表示和输出方式，但本文没有逐一隔离。

因此最稳妥的读法是：**在这两个小模型和这套问答构造中，换低排名真实材料能恢复一部分答案表现，单凭“更长”无法完整解释 Hard/Far 差异。** 这仍不是对内部注意力机制的直接观测，也不是一个能自动找出应删除文本的算法。[原文 §4.2、表 1](https://arxiv.org/html/2605.27294v1#S4.SS2)

## 第三组证据：这些恢复有多稳定，究竟恢复了什么？

表 2 不再重复原始分数，而是报告**每题配对后，Far 减 Hard 的平均变化**。作者按 question ID 做配对 bootstrap，报告 95% 置信区间，并用配对符号翻转随机化检验给 p 值。

直觉上，bootstrap 是反复按“题”重抽样，观察平均增益怎样变；配对符号翻转则以题内差值为单位，在零效应假设下比较观察到的增益与正负方向随机交换时的结果。两者都利用了同一题的可比性，不应改成不配对的总分比较。正文没有列出重采样次数，公开工件补足 bootstrap 和 sign-flip 均为 **20,000 次**。

| Reader | 指标 | Far − Hard | 95% CI | p |
|---|---|---:|---|---:|
| Phi-2 | EM | +6.0 个百分点 | [1.0, 11.0] | .036 |
| Phi-2 | 答案包含率 | +7.0 个百分点 | [1.0, 13.0] | .027 |
| Phi-2 | token F1 | +0.057 | [0.016, 0.099] | .009 |
| Qwen2.5 | EM | +4.5 个百分点 | [-0.5, 9.5] | .136 |
| Qwen2.5 | 答案包含率 | +9.0 个百分点 | [2.5, 15.5] | .010 |
| Qwen2.5 | token F1 | +0.068 | [0.015, 0.122] | .012 |

这里不能只摘“两个模型 EM 都上升”。Qwen 的 EM 区间跨过零，p=.136；按论文给出的检验，不能称其精确答案恢复已经显著。较一致的证据是两种模型的 F1 与答案包含率提高。

这与三种评分的性质一致：模型可能更容易在输出中提到正确答案，但未必稳定生成完全匹配的短答案。作者将它解释为答案选择与跨度质量的部分恢复；这是一种与指标相符的解释，**不是已经验证模型推理链或引用忠实性都改善**。此外，六组报告没有给出多重检验校正说明，宜完整呈现效应与区间，而不是只圈出 p<.05 的格子。[原文 §4.3、表 2](https://arxiv.org/html/2605.27294v1#S4.SS3)

## 第四组证据：换成 80-word 设置后，报告的恢复为何更弱？

作者还用 Qwen 做了 80-word 片段的敏感性检查。它回答的是：这种 Hard/Far 恢复是不是一个与输入构造无关、模型自带的固定属性？

报告的增益随实验设置而变化，不能把它当作模型固定属性。50-word 设置中，Qwen 的 Hard→Far EM 增益是 +4.5 个百分点，F1 增益为 +0.068；80-word 设置里，EM 增益变为 **0.0**，F1 只剩 **+0.020**。

这不是可以跳过的“效果略弱”。它告诉我们：同一种替换设计，换一种片段颗粒度，报告的增益就明显不同，但作者没有检验两种设置之间的增益差异是否统计显著。

同时必须防止把不兼容的数字拼起来：

1. 50-word 主实验的 Qwen gold-only EM 是 51.5；80-word 扫描的 gold-only EM 是 31.0。作者认为更短且围绕答案截取的片段，去掉了周围材料，使 gold-only 更容易。
2. 80-word **匹配对照**使用答案字符串过滤；图 1 对应的 **扫描**没有采用完全相同的过滤。原文 §4.4 特别说明，匹配设置的 gold-only 和 hard-19 EM 分别是 31.0、29.5。因此不能把图 1、表 1 和这段文字当成一张仅改变 H 的统一表。
3. 作者推测，较长片段可能保留了更多支持信息，减少片段之间的歧义，因此替换竞争者可恢复的空间变小。这个解释合理，但公开工件显示，**Qwen 的 80-word 设置最多生成 12 tokens，50-word 设置最多生成 20 tokens，输出清洗也不同**；干扰选段与位置的种子同样变化。因此这里不是只改变片段长度的干净消融，不能把跨设置差异全归因于支持信息。

这组结果的意义是：**必须把片段长度、截取策略、过滤、解码和清洗规则随结果一起报告，不能把 +0.068 当成 Qwen 对语义干扰的恒定系数。** 正文没有像表 2 那样列出其完整区间；公开 notebook 的留存输出补充了 80-word F1 增益区间 [-0.029422, 0.070029]、p=.437928，并不支持把该增益称为显著。这是工件留存统计，非本次独立重算。[原文 §4.4](https://arxiv.org/html/2605.27294v1#S4.SS4)

## 它与已有评估工作的差别在哪里

原文 §5 用已有工作定位自己的问题：Lost in the Middle 和 RULER 主要考察长输入中的位置、长度及任务复杂度；RAGAs 等框架区分检索与生成质量，已有工程分析也区分证据未检到、未放入或虽在场却未读出的失败。本文进一步比较同样数量、近似长度的真实材料，只替换检索竞争者的组成。

NoLiMa 则关注问题与目标信息之间缺少字面重叠时，模型能否找到隐含联系。本文考察的是另一轴：正确材料在场时，别的材料是否妨碍答案恢复。这些方向互补，不能由本文的小规模实验宣称先前工作都没有研究过干扰，也不能把它包装成整个领域首次发现相关文本可能有害。[原文 §5](https://arxiv.org/html/2605.27294v1#S5)

## 把它当作实验协议，而不是已经完成的机制证明

### Baseline 和消融到底提供了什么

本文没有复杂系统模块，所以不存在“删除某模块后性能下降”的传统消融。它真正做的是三个层次的实验：gold-only 提供参考，数量扫描描述随上下文累积的退化，Hard/Far 替换检查材料组成的作用。80-word 实验补充构造敏感性，Dense 曲线补充检索器变化的粗检查。

不能因此写成“BM25 和 Dense 都通过了严格等预算因果对照”：Dense 只做扫描，没有 Far 匹配对照。也不能说“四个 hard 已经足够产生全部剩余伤害”：论文没有在主设置里把 0、4、19 个 hard 与相同数量的 far 做完整剂量曲线。

### 需要主动保留的证据边界

- **控制的是一个具体替换，不是纯语义强度旋钮。** 从高排名换成低排名，同时改变了主题、实体和词项重叠等内容属性。结果支持这套检索负例替换的效果；“语义竞争”是作者对其机制的解释，尚未拆成独立因素。
- **近似等长主要由平均数支持。** token 均值很接近，片段数完全相同，但平均数无法排除个别题的长度或 gold 位置差异。尤其不能把它写成严格的逐例 token 匹配证明。
- **位置随机化不等于配对位置固定。** 工件确认 Hard 与 Far 用不同条件种子各自打乱，gold 位置没有配对固定；对留存的 200 对位置日志做只读汇总，Phi 同位置仅 11/200，Qwen 为 7/200。这是残留的位置因素，不等于已经证明增益全部来自位置，也不能由题目配对自动消除。
- **过滤答案字符串不等于人工审定负例。** 也没有对每段内容建立相关性、误导性或充分性的人工金标准。
- **输出指标存在构念边界。** inclusion 不检查模型是否同时说错；EM 又会因格式和冗长解释惩罚答案。没有证据表明输出长度、截断或遵循格式的差异完全不影响结果。
- **外推范围窄。** 一个抽取式 QA 数据集、两个小模型、一个主匹配检索器，不能直接代表前沿模型、多跳问答、代码仓库或动态工具调用。SQuAD 的答案知道且在场，也与真实代码定位中的缺失证据不同。
- **统计报告仍有缺口。** 区间反映所采样题目上的不确定性，不自动覆盖语料切分、gold 位置与干扰抽样种子或重复运行的变异。主实验是确定性解码，但这不消除输入构造的随机性。

### 正文与公开实验工件分开核查

本次除了全文，还只读检查了作者[固定提交的实验 notebook](https://github.com/repantis-ai/rag-semantic-competition/blob/6e9db091f9ee04cecf3d6e37002d7756f921d55c/notebooks/01_semantic_competition_snippet_controls.ipynb)和结果文件。应把“正文漏报”“代码可核”“尚未独立重算”分开：

- **Far 的具体定义可核。** 从排除 gold 后的 BM25 排名后半段打乱抽样，过滤答案后取十五段；不足时从整个排序榜尾倒扫补足。因而不能说所有 Far 都无条件来自严格后半段，更不能把它们当作人工认证的无关文本。
- **主实验解码可核。** snippet50 两个 reader 都是 `do_sample=False`、`max_new_tokens=20`。Qwen 输入上限 12,000；Phi 在 2,048 总长度中预留 20 个生成 token 和 8 个余量，实际输入上限为 2,020。代码启用截断，但没有完整逐例截断审计；平均输入长度低于上限不证明每题都未截断。
- **逐例 token 匹配并不存在。** 工件按空格分词截取至多五十或八十个词，没有根据 tokenizer 做逐例对齐、补齐或容差验收。snippet50 精确平均数为 Phi 1487.360→1495.880，Qwen 1519.330→1532.230；论文将其取整列出。
- **问题一致不等于输入完全一致。** 两个模型使用相同的 200 题抽样逻辑，但模型名/条件名参与不同随机种子构造，Far 片段和排列也可能变化。因此表 1 适合看每个 reader 内的 Hard/Far 差异，不是完全同输入的模型优劣排名。
- **80-word 的 inclusion 还有实现问题。** 工件使用双向子串判断，且没有先排除空预测，所以规范化空字符串或答案的局部子串也可能被计为包含答案。两模型的主 snippet50 代码已改为排空并只检查完整 gold 是否在预测里，因此这一问题不能用来否定主表 inclusion 增益，也不直接改变 EM/F1。未拿到逐题预测，无法确定它实际影响了多少样本；80-word 与 50-word inclusion 不应直接混用。两模型 snippet50 的输出清洗也仅基本一致，续写截断标记仍有小差别。
- **表值的内部一致性通过核对。** [Phi-2 汇总](https://github.com/repantis-ai/rag-semantic-competition/blob/6e9db091f9ee04cecf3d6e37002d7756f921d55c/results/phi2_bm25_snippet50_far_control_final_eval_seed42.json)、[Qwen 汇总](https://github.com/repantis-ai/rag-semantic-competition/blob/6e9db091f9ee04cecf3d6e37002d7756f921d55c/results/qwen_bm25_snippet50_far_control_final_eval_seed42.json)与表 1 一致，notebook 保存的统计输出与表 2 的四舍五入值一致。例如 Qwen F1 增益 0.068012，区间 [0.015350, 0.121581]，p=0.012399。
- **这不是独立复现实验。** 仓库没有主实验逐题原始 JSONL，只有代码、汇总 JSON 与 notebook 留存输出。本次没有重跑模型，也没有凭逐题预测重新计算置信区间；位置日志可核不等于全部输出可重算。安装依赖及模型、数据加载也没有全部固定 revision，复跑仍可能发生环境漂移。

这些检查使评价更具体：论文确实提供了有意义的匹配思路和一致的汇总结果，但还不能升级为“位置、逐例 token、输出协议全部固定后证明了纯语义竞争效应”。

## 这篇论文真正留下了什么

**证据支持的结论：**

1. 在本文的 50-word、二十片段设置下，用远排名真实材料替换十五个 BM25 靠前负例，两种 reader 的 F1 与答案包含率都得到部分恢复；Qwen 的 EM 恢复证据较弱。
2. Hard 和 Far 的片段数相同、平均 token 很接近，因此“材料变少、平均输入变短”不能解释观察到的恢复；但实际 gold 位置未配对固定，纯语义解释仍有残留因素。
3. 负例增加时，Qwen 的 EM 与 F1 保留率逐步下降；在已测到的 H=79 内，没有降到一半，不能伪造半衰点。
4. 效应在不同片段设置下变化，80-word 的 Qwen EM 恢复为零是重要负面结果；由于生成上限、清洗和随机构造也变了，不能只归因于长度。

**尚未证明的内容：** 语义竞争是所有长上下文退化的主要原因；任意较远文本都无害；只要等 token 就完全公平；该替换在所有模型或真实检索系统中有效；内部注意力、推理路径或动态 Agent 决策的因果机制已经确定。

读完应记住的是：要解释一种上下文“为什么有害”，先找能保留材料数量和长度、却改变其内容的对照；保留答案在场只是第一步；不同评分会揭示不同程度的恢复；构造敏感性和零结果必须进入主结论。

## 对当前代码上下文与 GraphLocator 研究的启发

以下是研究迁移建议，**不是本文已经完成的代码实验，也不是当前研究新增结果**。这里沿用当前研究的命名：C 为关键支持代码，P 为看似相关的旁支代码，I 为无关代码；R 是本仓随机补充，E 是仓外填充。标签用于研究者构造处理，不能泄漏给待测模型充当答案。owned 范围指节点自己拥有的源码区间；CIG 是 GraphLocator 保存代码关联与探索状态的图。

### 1. “同样多”至少有四种含义，不能用一个数字替代

最新研究记录把完整 prompt token、本仓可选候选数、真实 P/I 处理节点数、实际展示源码量分开，这是必要的。本文的二十片段只对应一个很简单的材料计数；代码里一个外层函数、类或模块会包含内部身份，不能直接照搬“二十段=二十节点”。

应继续沿用 owned 源码范围核查实际暴露，而非根据外层包围框把未显示的源码算作可见。现有 v3 r4 已做到四臂完整 prompt 长度差的约束、49 个有效 I 实例的 P/I 节点匹配；但节点数相同不等于 P/I 独占源码 token 相同。后者在当前记录中仍有明显逐例差异，因此估计目标要明确写成“当前构造策略下的替换效应”，不要写成“完全分离所有内容量差异的纯语义效应”。

### 2. 借鉴真实材料替换，并补上同位置约束

本文 Far 使用同语料库的真实文本，这使它比乱码更接近自然输入。代码实验可借鉴其思路：在冻结正确证据与候选口径后，用经审核且可操作的 I 或 R 内容匹配 P 的移除/替换数量与实际 token；记录每例而不只报告均值。

不过，当前末尾 E 填充虽然能补全总长度，也同时改变了外部内容所占比例和位置。若 P/I 处理量不同而只靠 E 把最终长度补齐，实验估计的是一组联合构造的效果，不能自动归为 P 的语义作用。可以先做离线验收，分别列出完整消息长度、被替换源码量、候选数、处理节点数、位置和 E 量，而不急着启动更多模型调用。

### 3. 对 GraphLocator，必须把实验放在真正的暴露位置

本文是一个固定输入、一次回答的 reader 试验，最直接对应的是“固定已收集材料后的末端读出”。它本身不支持“删掉最终材料就改善了 Agent 的探索路径”。

最新研究已经区分 GraphLocator 的检索相关性子调用、工具观察和 CIG 旧内容再暴露。若要研究探索偏移，可在首次合格 P 暴露之前恢复同一个状态，再分出自然输入、P 屏蔽、移除量匹配的 I 对照；需要同时固定或核验当时的候选登记、队列状态、输出预算和可见位置。这个设计比事后从最终图删内容更接近本文“同一题、同一 gold、只改竞争材料”的精神，但必须单独验证可回放性。

还要保留两个不可操作情形：P 嵌在必须完整保留的 C 代码中时，不应为了删净 P 破坏 C；没有合格 P 暴露的实例，不能被算成处理成功。未标注的新路径节点，也不能默认归 I。

### 4. 统计上优先看同例差值，同时保留失败与上限

可借鉴本文按问题配对的思路，按实例报告处理差值、区间和异质性，而不是把多条件、多轮次当成更多独立样本。若比较首次分叉，实验单位还需要包含冻结的前缀状态；同一实例多个状态并非天然独立。

同时必须分开候选召回、源码实际可见和最终判断三个阶段。当前十例开发已经暴露“GT 根本没进入候选，压缩无法补回”的上限；本文主动放入 gold，恰好绕开了这一问题，所以不能拿它证明筛选方法能补足真实检索缺失。它最有用的贡献不是替现有结论背书，而是帮助把下一步想估计的效应写得更窄、更可审计。
