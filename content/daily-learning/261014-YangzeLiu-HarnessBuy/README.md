# 论文精读：What Does a Harness Buy? Tokens, Mostly

> 精读日期：2026-10-14  
> 作者：Yangze Liu；Zhongyi Han*（*通讯作者）  
> 机构：山东大学  
> 原文：[arXiv:2610.04433](https://arxiv.org/abs/2610.04433) · [PDF](https://arxiv.org/pdf/2610.04433) · [代码与数据](https://github.com/YangzeLiu/what-does-a-harness-buy)  
> Venue：arXiv cs.AI / cs.LG / cs.SE，2026，v1  
> Tags：`Coding Agent` `Harness Engineering` `SWE-bench Verified` `Evaluation Noise` `Paired Experiment` `Statistical Power` `Cost`

## 先说结论：harness 主要买到的不是一个稳定的排行榜名次

这篇论文问了一个很具体、也很容易被营销材料说模糊的问题：**固定同一个语言模型和同一批任务，只替换包裹模型的 coding-agent harness，最终修复成功率到底会移动多少？** 作者把 Claude Code、mini-SWE-agent 和 OpenCode 接到相同模型上，在 SWE-bench Verified 上做任务内配对比较，并专门重跑相同配置来估计“什么都没改，只再跑一次”的自然波动。

最重要的发现有三层。第一，在 45 个最难任务上，换 harness 与原配置重跑都会让约 13% 的任务翻转，因此 2—5 个任务的领先不足以形成稳定排序。第二，在约 447 个任务的大池上，Claude Code 与 mini-SWE-agent 在两个 Qwen 模型上可以被界定为 **±5 个百分点内等效**；OpenCode 在 Qwen3.8-27B 上落后 7.9—9.2 个百分点，且差距与输出被截断后不恢复有关。第三，即便通过率接近，harness 仍会显著改变每一步携带的固定提示、上下文增长、步数和缓存计费，同模型同任务的成本最高相差约 3 倍。

所以标题中的 “Tokens, Mostly” 不是说 harness 毫无作用，而是把作用重新定位：**harness 很容易改变账单和失败方式，却不一定能在有限样本上买到可重复的 pass-rate 增益。**

## 先建立论文地图

### 核心矛盾

过去的公开比较常把“模型 + harness”整体当作一个 agent 报分。harness 改系统提示、工具、上下文压缩和停止策略后，分数变了，人们便倾向于把差值解释成 harness 的能力增益。但 agent 运行是随机的：同一配置重跑，成功与失败的任务集合也会变化。如果没有同配置重跑作为噪声尺子，也没有足够大的配对样本，就无法判断几分的差距是工程效应还是一次抽样。

作者因此没有再造一个 harness，而是建立一条测量链：

```text
公开榜单混合模型与 harness，且很少报告重跑波动
    ↓
固定模型、任务和预算，只替换 harness
    ↓
以“每个任务是否通过”为配对观测
    ↓
同配置重跑估计噪声；跨 harness 比较处理效应
    ↓
McNemar 精确检验、配对区间、等效性检验与功效分析
    ↓
再用轨迹终止原因和 token 分解解释显著差距与成本差距
```

这条链的关键是：作者先回答“差异是否超过噪声、实验能否看见它”，再讨论“为什么会有差异”。顺序很重要；若先看个别轨迹编故事，任何一两次成功或失败都能被解释成机制。

### 理解全文需要的五个概念

1. **Harness**：包在模型外面的运行系统，包括系统提示、工具接口、工具返回格式、历史压缩、重试、停止和预算策略。它不是模型参数，却决定模型每一步看见什么、能做什么，以及失败后是否有恢复机会。
2. **任务内配对**：比较 A 与 B 时，不把两个总通过率当作独立比例，而是看同一任务在 A、B 下的四种结果。真正提供差异信息的是“A 独过”和“B 独过”的任务。
3. **翻转率（flip rate）**：一对运行中结果不同的任务占比，即 \((b+c)/n\)。它衡量任务级结果有多不稳定；总分只变一点，不代表底层任务集合稳定，因为正反翻转可能互相抵消。
4. **等效性检验**：普通“不显著”只能说明没检出差异，不能说明两者相同。作者预先给出 ±5 个百分点边界，只有 90% 置信区间整体落在其中，才称两种 harness 在该边界内等效。
5. **统计功效**：如果真实差异存在，当前样本量把它检出的概率。45 个任务即使看见 3—5 个任务的差距，也可能没有足够功效分辨；447 个任务才有能力稳定讨论约 5 个百分点的差异。

## 实验如何把 harness 效应单独拿出来

### 三种 harness 覆盖三种设计风格

- **Claude Code 2.1**：闭源、工具和系统提示较重，会压缩不断增长的对话；遇到输出上限时能够重新提示模型继续。
- **mini-SWE-agent 2.4.6**：一个 shell 工具，固定提示很短，只裁剪很长的观察，不对整个对话做通用压缩。
- **OpenCode 1.18**：文件、搜索和编辑工具较多，也会压缩上下文；但在论文使用的模型接口上，输出被截断后不会自动恢复。

作者统一了三件影响最大的条件：每一步等于一次模型调用、每个 trial 最多 300 次调用、API 模型统一启用 reasoning effort=high。其余配置尽量保留产品默认值，因为研究对象就是生产 harness 的整体行为。这个选择有现实性，却也意味着比较的是“产品包”，不是某个单一模块的纯因果效应。

### 模型、任务与两档样本量

五个模型同时跑三种 harness：Qwen3.6-35B-A3B、Qwen3.8-27B、DeepSeek-V4-Flash、GLM-5.3-Flash 和 HY4-Preview。Claude Opus 5 只在 Claude Code 中作为闭源高端锚点，不能用来做跨 harness 比较。

SWE-bench Verified 的 500 个任务中，8 个验证时需要公开网络服务，离线条件下无法运行，因此剩 492 个。作者按 benchmark 的人工难度标签拆成：

- **hard45**：42 个预计 1—4 小时、3 个预计超过 4 小时的最难任务；五个模型均覆盖，并对多种配置重跑。
- **pool447**：其余 447 个任务；只在两个 Qwen 模型上跑完整三-harness 网格，以获得能够界定小效应的样本量。

这不是训练/测试划分。hard45 用于观察最可能需要 harness 帮助的困难任务与重跑噪声；pool447 用于提高估计精度。两者不能合并成一个同质结论。

### 离线约束不是小细节

早期开放网络运行暴露了严重泄漏：DeepSeek 与 Qwen 的 439 个 trial 中有 312 个从 GitHub 获取了上游修复，其中 310 个随后进行了编辑；这类 trial 的通过率为 96%，而没有联网抓取的只有 71%。作者丢弃所有联网结果，并在网络层封锁除模型端点外的访问。

这个审计非常重要。若只看最终测试通过，agent “自己修好”和“下载标准答案”会得到同一个标签。论文由此也提醒：工具权限是实验处理的一部分，不能只在 prompt 里要求“不联网”而不在执行层验证。

### 评分、失败与统计协议

每个单元格报告预定的第一次运行，且在看结果之前固定。基础设施异常会从相同配置补跑，不替换已经得到的可评分首跑；上下文溢出、时间上限、输出上限和步数上限则保留为失败，因为它们正是 harness 能否管理资源的一部分。

任务级比较使用精确 McNemar 检验，只关注 A 独过的 \(b\) 个任务和 B 独过的 \(c\) 个任务。直觉上，如果两种 harness 真没有方向性差异，那么这些不一致任务应大致各占一半。作者同时给出配对 Newcombe 置信区间，不让单个 p 值承担全部解释。

pool447 另做 ±5 个百分点的双单侧等效性检验（TOST）。主表没有对六个成对比较做多重校正，但作者补充 Holm 校正后的解释；这是阅读“小 p 值”时必须保留的边界。

## 结果一：45 个困难任务无法稳定给 harness 排名

hard45 的主表固定同一批 45 个任务，横向改变 harness。每个模型三列中的差距为 2—5 个任务：

- Qwen3.6：Claude Code 11/45，mini-SWE-agent 15/45，OpenCode 11/45；
- Qwen3.8：19/43、17/45、17/45；
- DeepSeek-V4-Flash：21/45、22/45、19/45；
- GLM-5.3-Flash：22/45、20/45、18/45；
- HY4-Preview：23/45、26/45、21/45。

mini-SWE-agent 在五个模型中的三个领先，Claude Code 在两个领先，但所有成对差值的 95% 区间都跨过 0。更关键的是，同一个配置重跑，分数本身最多也移动 3 个任务。HY4-Preview 上 mini 相对 Claude Code 高 6.7 个百分点、相对 OpenCode 高 11.1 个百分点，直觉上似乎不小，但精确检验分别只有 \(p=.45\) 和 \(p=.12\)。

这里不能写成“三者一样好”。正确结论是：**在 45 个任务的分辨率下，观察到的排序不能与重跑波动区分。** 未拒绝差异不等于证明等效。

## 结果二：447 个任务才能给出有边界的结论

Table 1 是全文最重要的结果表。每行固定模型和任务，只改变 harness；A、B 是各自通过数，\(b\)、\(c\) 是独过任务数，差值和区间来自配对结果。

### Claude Code 与 mini-SWE-agent：可在 ±5pp 内判等效

Qwen3.6 上，Claude Code 通过 310 个、mini 通过 318 个，配对差值 -1.8pp，95% 区间 [-5.2,+1.6]，\(p=.37\)。Qwen3.8 上为 347 对 353，差值 -1.4pp，区间 [-4.2,+1.5]，\(p=.43\)。用于等效性判断的 90% 区间均完全落入 ±5pp，因此作者能说：**在这两个模型、这批任务和这套预算下，最重与最轻的两个 harness 在五个百分点边界内等效。**

这比“没有显著差异”强，但边界是人为选择的操作阈值。论文没有证明差异为 0，也没有证明其他模型、benchmark 或预算下仍等效。

### OpenCode：在 Qwen3.8 上有可复现的大差距

Qwen3.8 上，Claude Code 相对 OpenCode 高 7.9pp，95% 区间 [+4.3,+11.5]；mini 相对 OpenCode 高 9.2pp，区间 [+5.5,+12.9]，两者 \(p<.001\)，且经六次比较的 Holm 校正后仍成立。

Qwen3.6 上 mini 相对 OpenCode 高 4.7pp，未校正 \(p=.02\)，但多重校正后不再显著。因此论文中真正越过噪声和多重比较门槛的，是 Qwen3.8 上 OpenCode 的两个失分比较，而不是“OpenCode 对所有模型都差”。

## 结果三：任务会翻转，分数却可能看起来很稳

Figure 2 把三类配对放在同一纵轴：相同 harness 重跑、固定模型换 harness、固定 harness 换模型。纵轴是任务结果翻转率，不是总分差。

- hard45 的同配置重跑中位翻转率为 13%；
- 固定模型换 harness 也是 13%；
- 换模型为 22%。

这解释了一个常见错觉：一次运行 A 比 B 多过 2 个任务，看起来总分很接近；实际可能有 6 个任务 A→B 失败、4 个任务 B→A 成功，底层有 10 个任务翻转。净差只剩 2，但行为稳定性远低于总分显示的程度。

作者还检查 harness “赢了哪些任务”能否在第二轮重现。在 6 对有双方重跑的 harness 比较中，12 个在两轮都发生方向性分裂的任务里，只有 5 个保持同方向、7 个反向，二项检验 \(p=.77\)。也就是说，hard45 上并不存在一组可稳定归因给某个 harness 的获胜任务。

### Figure A2：为什么 45 个任务看不见小效应

附录 Figure A2 横轴是配对任务数，纵轴是达到 80% 功效时可检测的最小百分点差异。按论文观察到的约 14% 不一致率，45 个任务连任何差异都达不到 80% 功效；其 50% 功效对应约 12.9pp。直到约 55 个任务才可能在极端方向一致时达到 80% 功效，447 个任务则可检测约 5.2pp。

因此，小样本上“差 5 分但不显著”不是模型告诉我们“没有差”，而是设计本身没有能力分辨。作者据此建议：报告任何 harness 增益时，都应同时报告同配置重跑噪声和该样本量的分辨率。

## 结果四：能跨过噪声的差距，来自失败恢复而非神奇提示词

论文没有停在 OpenCode 落后，而是回到轨迹看 trial 如何结束。Figure 3 的每根柱子按结局分成通过、普通失败、输出截断、上下文溢出、超时和步数耗尽。

### 输出截断后是否恢复

Qwen3.8 的 pool447 中，OpenCode 有 33 个（附录终止统计口径为 34 个）trial 在 32k 输出上限处终止。Claude Code 也会碰到相同供应商上限，但 66 次事件中有 64 次会重新提示并继续，最终只有 1 次成为终止失败。

OpenCode 的输出截断任务通过率只有 7.9%，其余任务为 75.9%；34 个终止 trial 中有 32 个仓库完全未修改，中位数只走了 11 步。若从评分中剔除这类 trial，OpenCode 与另外两种 harness 的差距大约减半。

这是强关联证据，但仍不是完整机制证明：输出截断可能只是模型陷入冗长推理的症状。作者把 Claude Code 式继续提示移植到 41 个受影响任务、每个做两次恢复尝试，结果没有显著把差距降为零；相同任务的失控推理在重跑中只约 15% 复现。恢复策略“可能有帮助”，但论文没有证明它足以解释全部差距。

### 上下文溢出与过早停止

mini-SWE-agent 不做通用压缩，Qwen3.8 在 hard45 有 11/45 次溢出、pool447 有 18 次。可这些任务只有 3/11 和 6/18 被其他 harness 修好，而且 hard45 的 11 个溢出中有 7 个在重跑时再次溢出。这更像困难任务导致长轨迹，而不是“溢出本身造成了所有损失”。

Qwen3.6 没有输出截断问题，OpenCode 仍比 mini 低 4.7pp。OpenCode 在 GLM-5.3 上中位步数也更少，暗示过早停止可能是另一条失分路径，但作者没有识别出确定的停止机制。因此不能把全部 OpenCode 差距归因于单一 output cap。

还有一个公平性问题：hard45 的本地 Qwen 运行中，OpenCode 的软超时为 5,760 秒，而 Claude Code 可运行到 36,000 秒；Qwen3.8 有 6 个 OpenCode trial 在仍有 patch 进展时超时。这是 harness 的真实默认行为，同时也是一个与 harness 身份捆绑的时间预算混杂。结果适合评价“产品默认包”，不适合声称提示或工具接口单独导致差异。

## 结果五：同样的模型和任务，账单可差三倍

作者把输入 token 分为 cache miss、cache hit，再加输出（含 reasoning）并按统一价目表重算。Figure A3 上半部分看 token，下半部分看人民币成本；同一模型下三根柱子的任务集合相同。

以 GLM-5.3-Flash 为例，每个 trial 的估算成本是 Claude Code 1.81 元、mini-SWE-agent 0.97 元、OpenCode 0.56 元，最贵与最便宜超过 3 倍。DeepSeek-V4-Flash 则是 0.98、1.02、0.66 元，模型供应商对 cache hit 的定价会改变差距大小，但没有改变本实验中的排序。

### 成本差从第一步就开始

三种 harness 每次调用都带固定前缀：Claude Code 16,581 tokens，OpenCode 7,025，mini 829；第一步完整输入相应为 17,134、7,579、1,382。工具返回并没有这么大差别：平均字符数约 1,237、1,186、1,103，90 分位也都约 3.1k。

Figure 4 把每次调用的输入 token 对步数作图。三条带状轨迹从第一步便错开，且随步数增长：GLM 上 Claude Code、mini、OpenCode 的每步增长中位数分别为 937、648、681 tokens；DeepSeek 上为 1,308、1,037、1,116。作者根据轨迹重建推断 Claude Code 会把模型 reasoning 留在历史中，但供应商 usage 不直接拆分 reasoning 与文本，因此这是推断而非直接观测。

成本最终由三项共同决定：固定前缀、每步上下文增长、总步数。GLM 上平均步数为 88.1、80.2、55.1；Claude Code 既每步更重又走得更多，于是最贵。换一个缓存价格表会改变倍数，换一个偏好短步或长步的模型还可能改变哪个 harness 最便宜。论文证明的是**账单对 model×harness×价格表交互敏感**，而不是一个永久成本排行榜。

## 消融、负结果与迁移检查

### “自家模型配自家 harness”没有额外优势

DeepSeek 自有命令行 harness `dsh` 在 hard45 上通过 21/45，与 Claude Code 相同、比 mini 少 1 个；每 trial 成本 1.04 元，也位于三者范围内。单个模型和任务集不能证明“home-field advantage 永不存在”，但这次检查没有支持它。

### Claude Code 的工具和旧版本消融没有改变得分

在 Claude Opus 5 上，作者做 bash-only、去掉 shell 以及旧版 1.0.100 三种设置。它们的通过数都在三次控制运行的一题范围内。旧版成本只有当前版的 0.44 倍，主要因为默认没有 extended thinking；这说明版本升级明显改了账单，却没有在 45 个任务的分辨率内改出稳定分数。

这组消融不能推出“工具设计不重要”，因为它只覆盖一个模型、45 个任务，而且多种工具能力可能被 bash 替代。能说的是：在这个设置中，移除某一表面工具并未产生超过重跑噪声的效果。

### Thinking 与 harness 有交互，而不是统一增益

关闭 Qwen3.6 的 thinking 后，Claude Code 和 OpenCode 分别上升 2.2、3.4pp，mini 下降 11.1pp（\(p=.04\)）。HY4-Preview 配 Claude Code 关闭 thinking 也下降 11.1pp，但单次比较 \(p=.27\)。方向依赖 model×harness，网格又太小，论文只把它作为值得追踪的交互线索，不能归纳成“thinking 应该开/关”。

### Terminal-Bench 的外部检查仍看不出排序

在 Terminal-Bench 2.1 的 53 个任务上，三种 harness 有 50 个共同可评分任务，mini、OpenCode、Claude Code 分别通过 19、20、20 个，所有 McNemar 比较 \(p=1.0\)。这提供了一次跨 benchmark 的方向检查，但样本仍小、只用了一个模型，也不能证明 SWE-bench 上的结论普遍成立。

Zhongyi Han 是山东大学软件学院教授、博士生导师。其[学校主页](https://faculty.sdu.edu.cn/hanzhongyi/en/index.htm)列出的长期方向包括机器学习、基础模型、Agentic AI、AI for Science 和医学影像分析，重点积累是开放环境中的鲁棒机器学习、域适应、分布外检测与弱监督学习；加入山东大学前曾在 MBZUAI/CMU 与 KAUST 从事博士后研究。与本文最直接的联系不是传统医学影像主题，而是**分布变化、鲁棒性与可辨识评估**：论文把 coding-agent harness 当作系统条件变化，并用重复、配对和功效分析避免把随机波动误当改进。

## 证据审计：这篇论文证明了什么

1. **在明确边界内的等效**：对两个 Qwen 模型和 pool447，Claude Code 与 mini-SWE-agent 的差异可被界定在 ±5pp 内。这是等效性证据，不只是“不显著”。
2. **小样本 harness 排名不可靠**：hard45 的跨 harness 翻转率与同配置重跑中位数同为 13%，且方向性获胜任务不复现；45 个任务没有能力稳定分辨常见的几分差距。
3. **某些系统失败路径会产生实质损失**：Qwen3.8 上 OpenCode 的 7.9—9.2pp 劣势跨过噪声与多重校正，轨迹显示输出截断且不恢复与大量未编辑仓库高度关联。
4. **成本是独立结果变量**：固定模型和任务，harness 的固定前缀、上下文增长和步数可让成本相差至约 3 倍；通过率相近不代表运行代价相近。
5. **污染控制必须在执行层完成**：早期联网 trial 大量取得上游修复，足以把通过率抬到 96%；作者丢弃它们后再离线运行，说明 agent benchmark 的工具边界会直接决定构念有效性。

## 它没有证明什么

- 没有证明 harness 对通过率“永远没用”。等效结论只覆盖两种 harness、两个 Qwen 模型、±5pp 边界和 SWE-bench Verified 的 pool447。
- 没有证明 OpenCode 的差距完全由 output cap 导致。恢复移植未得到显著结论，Qwen3.6 上没有截断仍存在较小差距。
- 没有分离系统提示、工具接口、压缩、停止和时间预算各自的独立因果效应；主实验比较的是产品整体。
- 没有证明成本排序可跨供应商保持。价格表、缓存折扣、模型每步行为和本地算力均会改变账单。
- 没有建立所有 coding-agent benchmark 的普遍噪声率。13% 来自本文设置；新任务、模型和温度需要重新估计。
- 没有证明一次首跑就是模型“真实能力”。作者只是把首跑作为预先固定的可比较估计量，并用重跑刻画其不稳定性。

## 阅读后真正应该记住的六件事

1. **先测重跑噪声，再谈处理增益。** 没有同配置复跑，几分差距没有可靠参照系。
2. **总分差和任务翻转率是两件事。** 净差接近 0 时，底层可能仍有大量相反方向的任务翻转。
3. **“不显著”不等于“等效”。** 若要主张差不多，必须预设有意义的等效边界并让区间落入其中。
4. **样本量要由配对不一致率决定。** 在本文约 14% discordance 下，45 个任务对常见的小效应几乎没有分辨率，447 个任务也只够看约 5pp。
5. **harness 最可信的价值可能是减少可避免的失败路径。** 输出截断恢复、压缩和离线可用工具比“提示更聪明”更容易被轨迹证据验证。
6. **成功率、过程稳定性和成本必须并列报告。** 一个 harness 可以分数相近、任务集合不稳定、账单却高三倍。

## 对当前研究的启发

当前 causal-review 研究正在把真实暴露、候选生成、工具调用、最终定位与 gold judgment 分层记录，并已观察到同一输入重跑时目标有时丢失、有时恢复。本文最直接的价值是给这类实验补上“噪声对照”和“可辨识边界”。

### 1. 给每个 context treatment 配一个同配置重跑对照

当前相对剂量实验不应只比较 baseline 与 BM25/name/random 等 treatment。至少抽取一部分 case×agent 单元原样重跑，分别计算：

- 行/文件/区域命中的任务级翻转率；
- 过预测宽度、候选数、实际读取量和最终引用的连续差异；
- treatment swap 的翻转率是否明显高于 rerun flip rate。

如果 treatment 与 rerun 的任务级翻转率相当，就不能把一次运行中的正负差直接解释为 context 因果效应；它首先是“尚未超过噪声”的结果。

### 2. 把“净效果”与“谁被翻转”分开

现有实验中某些 arm 的 recall 都为 1，但 line/file F1 因过预测下降。建议像本文区分 score gap 与 flip rate 一样，另外记录：目标是否被命中、候选边界是否扩张、gold 之外新增了多少块、最终判断是否正确。即使平均 F1 抵消，任务级的“获益/受损”对也能揭示异质性。

### 3. 用 discordance 反推下一阶段样本量

8-case 或 13-case 队列只适合侦察机制，不适合稳定估计几百分点效果。可先用重复数据估计不同终点的配对不一致率，再画出样本量—最小可检测差异曲线；论文叙事应明确当前实验是 mechanism probe、precision study 还是 confirmatory comparison，避免让小样本承担总体优劣结论。

### 4. 把工程可靠性改进与科学处理效应分账

10 月 14 日新增的无损日志、源码缓存、事务化事件和语义一致性回放，提高了可观察性与复现能力，但本身不是 context treatment 的科学证据。本文恰好提供对应语言：这类改进首先改变“harness 能否丢数据、能否恢复、账单多少”，只有在冻结配置并重新运行配对实验后，才能讨论对定位或判断的效应。

### 5. 报告“实际暴露账单”，不要只报配置剂量

本文把固定前缀、每步增长和步数拆开，说明名义上同一任务的真实 token 消耗可差数倍。当前研究也可并列报告：提供给 agent 的候选上下文、工具实际返回、模型实际读取/保留、最终答案引用四种 exposure。这样才能区分“处理分配了更多上下文”与“模型真的利用了更多有效证据”。

## 总评

这是一篇结论克制但实验观念很强的论文。它最有价值的部分不是宣布哪个 harness 最好，而是把三类经常混在一起的量拆开：**通过率净差、任务级不稳定性、资源成本**。大样本等效性检验让“差不多”有了边界，小样本重跑让“领先几题”失去虚假的确定感，终止原因与 token 分解又把工程系统真正能控制的变量落到可观测轨迹上。

它的限制也同样清楚：主结果集中在一个 benchmark，pool447 只覆盖两个模型，产品级比较没有分离组件效应，部分机制恢复实验功效不足。但对任何正在做 coding-agent context intervention、trajectory attribution 或 repository-level benchmark 的研究，这篇论文都给出一条难以回避的最低标准：**每个处理差都应和同配置重跑并排，每个“无差异”都要说明等效边界与功效，每个工程改进都要和科学效应分账。**
