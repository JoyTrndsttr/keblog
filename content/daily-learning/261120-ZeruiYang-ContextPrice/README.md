## 一、今天为什么读它

前几篇讨论了检索能否找到证据、上下文怎样干扰推理，以及智能体评估如何控制信息和预算。这篇进一步问：即使少读了文件、少放了 token，整个系统是否真的更便宜？

这对正在比较直接裁决与筛选后裁决的研究很重要。筛选器自己的调用要付费，缓存失效要付费，模型重新寻找被删除信息也要付费。论文把这些容易混在一起的量拆开，并通过大量负面结果提醒我们：一个局部过程更高效，未必意味着端到端更高效。

先给结论：本文在三个模型家族、多个智能体框架和超过两万次运行中发现，添加检索代码经常减少搜索，却没有建立稳定修复增益；删除旧观察在缓存便宜时经常涨价。两万次是包含条件和重复的运行数，不能理解成两万个独立任务。

原文可以直接确认工业研究机构署名及两位通讯联系人，但没有给出每位作者的具体职务。公开检索中的同名个人主页不足以独立确认第一作者完整履历，因此这里不补写头衔。本文的可信度主要来自公开实验协议、确认实验、负面结果和测量偏差审计，而非作者名气。

## 二、先理解前缀缓存：服务器不能跳过中间的修改

智能体每走一步，都把问题、历史对话和工具结果发给模型。若相邻两次请求的开头完全相同，服务器可能复用这一段的计算，这就是前缀缓存。

设第一轮提示为：

```text
固定说明 | 旧观察 B | 后续历史 S
```

下一轮删掉 B 后变成：

```text
固定说明 | 后续历史 S
```

虽然 S 的文字没变，它在序列中的位置和前文变了。缓存匹配到修改处就结束，S 要重新计算。图2把这个机制画成“稳定前缀、被删块、失效后缀”三段，很适合记住：删除一段旧内容的代价，会落到它后面的内容上。

### 2.1 三类 token 必须分别记账

本文的归一化成本为：

```text
Cost(c,p) = U + cC + pO
```

U 是未缓存输入 token，C 是缓存输入 token，O 是输出 token。把一个未缓存输入 token 的价格设为1，c 和 p 分别表示缓存输入与输出的相对价格。

主要比较 c=0.1 与 c=1，默认 p=4。前者相当于缓存输入打一折，后者没有缓存折扣。表中的 K 表示千个归一化成本单位，不是美元，也不是全部输入 token 数。作者还在 c∈{0.025,0.05,0.1,0.25,0.5,1}、p∈{2,4,6,8} 上重新计价。这个价格区域用来做敏感性分析，不应直接当成今天各供应商的报价。

输出也不能忽略：在 c=0.1 的设置下，输出约占成本19%–38%。只汇报“prompt 从多少K降到多少K”，会漏掉这部分。

### 2.2 删除何时回本

设删除 B 个 token，会让后面的 S 个 token 失去缓存，之后还有 R 次请求。暂时假设后续行为完全不变：

```text
删除获益：RcB
一次性重算代价：(1−c)S
值得删除的条件：RcB > (1−c)S
```

例如 B=1000、S=5000、c=0.1。若还有10次请求，总共省1000单位，却需要额外支付4500单位，净增3500。要到45次后续请求才刚好回本，超过45次才开始赚钱。

这里有两个关键前提：未来还要运行多久是估计值；删除后模型的行为也未必不变。因此这个公式是固定行为下的核算规则，不能独立保证在线节省，更不能保证答案质量。

## 三、它怎样设计实验，以及质量指标哪里有隐患

### 3.1 数据、模型和框架

实验覆盖 SWE-bench test、SWE-bench Verified 和 Loc-Bench。初始80个 SWE-bench test 任务不属于 Verified；随后又使用219个新 Verified 任务确认添加证据的效果，以及201个新任务比较历史管理。定位实验另有224个 Loc-Bench 任务，其中40个用于探索、184个留作定位结果比较。

七个模型包括 Qwen3.5-4B/9B、Qwen3.6-27B、Qwen3-Coder-30B-A3B、Qwen3.8-27B、Gemma-4-26B-A4B 和 GLM-4.7-Flash。框架包括最小 bash agent、mini-SWE-agent 2.4.6 和 SWE-agent 1.1。不同家族或框架的提示格式、服务版本及步数上限存在差异，因此跨模型比较不能视为只改变了模型权重。

最小框架使用50步、64K上下文；工具输出超过6000字符时保留头尾各3000字符。采样温度0.7、top-p 0.8，每次输出最多2048 token。早期 mini-SWE-agent 添加证据复现实验也限制50步，后续历史管理等实验使用250步。看到同一框架名称时，还要继续查步数限制。

统计单位是任务。重复运行先在任务内平均，再做配对比较；使用2000次任务级 bootstrap、95%区间。预设方向检验在实验家族内做 Holm 校正。基础设施失败与模型未提交、上下文超限分别处理，不能统一理解为失败全部删掉。

### 3.2 三种质量不能互换

- **Resolved**：补丁是否通过隐藏测试，是修复任务的主要结果。
- **On target**：是否编辑到标准补丁涉及的函数，只是代理指标。
- **Acc@k**：前k个定位候选是否包含目标函数，是定位指标。

编辑到目标函数并不保证修对；定位名单变好也不保证后续修复提高。文中不少附加实验只测 on-target，并未进行官方修复评分。

“官方”和“本地”修复评分也要分开。本地环境能够执行部分仓库测试，只在标准补丁能通过该环境的任务上评分，任务分母可能与官方评分不同。不能把两个百分比直接拼在一起。

### 3.3 一个必须提前知道的评分缺陷

本文两种修复评分都使用记录的、已跟踪文件的工作区差异，而不是完整的基准提交相对变更，也不是智能体提交的补丁文件。

附加审计发现：1%–4%的运行可能漏掉已暂存修改；相关运行中，提交补丁与工作区补丁约四分之一不同。作者明确说明，尚未在完整补丁定义下重算本文全部质量结果。

这不会直接推翻 token 成本核算，但会削弱几百分点级别的质量解释。附录R中，本地与官方报告在可比较的564个结果上有554个一致，也不能证明补丁抽取完整。它们可以在同一个不完整补丁上达成一致。

## 四、加上下文：搜索减少了，钱却花得更多

### 4.1 添加的究竟是什么

作者根据 issue 文本，在基准提交的仓库上用稠密检索排序函数，不读取标准补丁。排名前三的非测试函数展示完整源码，后七个只给位置；再通过代码图补充相关定义、被调用函数和同文件附近定义，总包控制在1000行左右，约14K token。

主要条件：

| 条件 | 内容与生命周期 |
|---|---|
| E0 | 不额外添加证据 |
| EL | 只放前三个候选函数源码，约1.2K token |
| E2 | 完整证据包一直保留 |
| E5 | 先放完整包，首次编辑或第8步时替换为位置索引 |
| E5r | 长度匹配的随机代码 |
| EI | 只给位置 |
| ED / EDm | 按需读取扩展；后者在触发点移除已读扩展 |

这不是“任意上下文越多越好”的实验。前三个函数及排除测试文件的规则经过初始批次离线定位表现选择；最初检索失败的任务在运行前被移除，部分由同仓库备用任务替代。新任务确认实验因此尤其重要。

### 4.2 搜索收益比较稳定，成本收益没有成立

图4和表4的主要例子如下，费用按 c=0.1、p=4：

| 设置 | E5 相对 E0 的读与搜命令 | 相对成本 |
|---|---:|---:|
| Qwen3.6-27B，SWE-bench test | −5.97次，约−26% | +42% |
| 同模型，Verified | −6.64次，约−32% | +36% |
| 同模型，219个新 Verified 任务 | −4.87次，约−26% | +42% |
| 同模型，Loc-Bench | −4.52次，约−19% | +36% |
| Qwen3-Coder，SWE-bench test | −2.97次 | +95% |

因此摘要中的“成本增加33%–42%”不能覆盖所有模型，Coder 这一组的增幅更大。即使 c=1，前三个主要修复设置也分别涨价约33%、25%、29%。

随机代码没有带来同样的搜索减少。这支持“有用内容改变了探索”这一解释，但仍不能把少搜直接等同于修复进步。

图5进一步表明，完整包持续保留 E2 比按时转索引的 E5 更贵。移除大包的成本回收条件在91%–97%的运行中满足，约省24%–26%；小型 EL 包回本机会只有42%–44%。删除是否划算，取决于删除量、后缀长度和剩余请求数，不能只看当前上下文大小。

### 4.3 修复结果没有确立稳定提升

初始 test 的官方修复率差为−1.9个百分点，Verified 为+3.8个百分点，均未建立可靠改善。新确认实验在217个可评分配对任务上差异约0，并通过预设±5个百分点的等效检验。

图7中即便加入标准答案位置的 oracle 条件，+5.8个百分点的结果也没有通过其显著性判断。这里的含义是当前证据不足以建立提高，不代表真实效果必定为零。

加入可执行测试环境的2×2实验同样未支持“证据包与执行能力产生稳定协同”：有执行时证据的官方增益约−0.3个百分点，交互约−1.6个百分点。执行环境本身的增益在未校正时显著，但将三个检验一并校正后未过阈值。

### 4.4 框架和生命周期改变结论

mini-SWE-agent 的搜索减少约6%，远小于最小框架的约34%。前8个命令的早期收益相近，但完整轨迹不同：一方面任务更早提交，另一方面50步上限也压缩了比较空间。

Gemma 的整个轨迹没有复制搜索减少，尽管前8步仍有收益。原因线索是它常在第2步创建草稿文件，提前触发“首次编辑后撤掉证据包”，而 Qwen 通常到第6步才触发。作者改成固定第8步，或只认已跟踪文件修改，可以延长早期效应，但完整运行的显著收益仍未建立，费用仍高约29%–31%。

这说明名义相同的触发器，可能让不同模型实际上看了不同长度时间的证据。修正协议后仍应报告否定结果，不能只挑前几步画图。

## 五、定位任务中，检索更像补充候选

在184个留出 Loc-Bench 任务上，把检索排序追加到智能体自己生成的定位名单中，三个模型的 Acc@10 分别提高约15.2、20.1、14.1个百分点。Qwen3.6-27B 的例子是0.386到0.538。

这是本文比较明确的正向发现，但它来自最终候选合并，不等于把大段代码加入每轮提示，也不等于修复成功率提高。

还要检查名单长度：智能体原来经常只给1–2个候选。仅追加它自己已见过的函数，也能提高约9–14个百分点。检索相对于这种补齐的额外收益约6.5、6.0、1.6个百分点，属于描述性对比。若只与严重欠填的名单比较，容易把“多给几个位置”的作用都算给检索。

追加排序不产生额外大模型 token，但检索器计算并没有完整计入本文的 token 价格模型。多智能体名单合并只再提高1–3个百分点，却需要2–4倍模型运行成本。

### 图8为什么不能读成“80%的证据没用”

作者根据基线轨迹，区分证据包里的行是很快读到、后来费力搜到、修改后才读到，还是从未读到。按其可计数行定义，约80%的包内容在基线中从未读到，7%很快读到，12%需要继续探索才出现。

“没在基线读到”不等于“无关”，更不等于“对干预组无用”。这只是可观察的行为分类，而且只有约59%的行满足唯一且长度足够等计数条件。费力探索部分与搜索节省相关，但相关系数约0.27，并非因果证明。

已有证据再次出现也有合理原因：部分重读发生在文件修改后，或证据包已被移除后。不能把每一次重复读取都当成浪费。

## 六、删上下文：同一方法在两种价格下反转

主要历史管理方法：

- **MR**：不删除。
- **MM10，滚动删除**：每轮只保留最近10个工具观察。
- **MB，批量删除**：积累到20个观察时删掉旧10个。
- **MAR，回本规则**：保留最近10个，对更早观察按前述不等式决定是否删除。

MAR 用先导实验估计剩余步数，形式为 R=min(250−t,max(59−t,25))。它仍是估计器，不是提前知道轨迹终点。

### 6.1 201个新任务的确认实验

| 方法与模型 | c=0.1 相对不删除成本 | c=1 相对不删除成本 |
|---|---:|---:|
| 滚动删除，Qwen3.6-27B | +116% | −19% |
| 滚动删除，Qwen3-Coder | +87% | −25% |
| 回本规则，Qwen3.6-27B | +2.8% | 约−26% |
| 回本规则，Qwen3-Coder | +1.8% | 约−21% |

图3最重要的是曲线穿过零线：在一种价格下看起来最佳的方法，换个缓存折扣就可能落后。

回本规则已经比滚动删除便宜很多，但相对于不删除，费用差的单侧上界分别约+8.3%和+11.4%，未通过“最多贵5%”的非劣检验。不能把+2.8%的点估计说成已经证明差不多。

把规则改成适配 c=0.025，会减少删除量；相对于原规则确实省钱，但相对于完全不删除，仍未稳健通过非劣界限。规则改善与击败默认基线是两件事。

### 6.2 跨框架、跨家族的边界

在 SWE-agent 中，Qwen 的滚动删除在 c=0.1 增加101%，在 c=1 降低29%；另一组78个不同仓库任务也出现同向反转。回本规则的缓存账面收益被更长运行抵消，平均步数约从92增到116。

GLM-4.7-Flash 原本运行很长，平均约171步，因此删除后有更多请求可以回收成本。它的回本规则在 c=0.1 点估计省12.7%，通过成本非劣检验，且因减少上下文超限而改善本地质量。Gemma 的相应结果则没有这样理想。

因此，本文不能总结为“永远别删”。正确结论是，价格、轨迹长度、模型补偿行为和上下文失败率共同决定结果。

## 七、把缓存重算与行为反应拆开，但别误叫因果中介

图9的办法很直观：先取不删除时的真实轨迹，固定其中每条动作和输出，只重新构造“如果用了删除规则，每次提示会怎样”。记：

```text
C0：原始运行成本
Cf：固定原动作与输出、仅重算提示的成本
C1：实际启用删除后重新运行的成本
C1−C0 = (Cf−C0) + (C1−Cf)
```

第一项是固定动作下的直接记账差，第二项是实际运行相对固定轨迹的剩余差。作者明确把它称为核算恒等式，而非已经识别的因果中介效应，因为同一串动作未必在删掉信息后仍然合理或会被模型选中。

表6的 Qwen mini-SWE-agent 例子：

| 方法 | 固定动作部分 | 剩余部分 | 实际总差 |
|---|---:|---:|---:|
| 滚动删除 | +90% | +26% | +116% |
| 批量删除 | −3.4% | +8.2% | +4.9% |
| 回本规则 | −3.7% | +6.5% | +2.8% |

后两行最值得注意：静态重放本来省钱，真实模型却多读、多搜、运行更久，把节省吃掉了。Qwen 的滚动删除增加约5步，增加读取和搜索，但没有对应增加编辑。

SWE-agent 的现象更强：批量删除固定动作省约21%，剩余增加约45%，最终涨约24%。把历史压缩算法放在固定日志上评估，可能错过这一整块在线代价。

## 八、作者还试了哪些补救，为什么没有简单赢家

### 8.1 确定性摘要与恢复入口

作者把旧观察替换成简短、确定性的摘要，保留函数定义线索、搜索路径、测试和编辑确认，同时允许按原步骤取回原观察。这样无需另请大模型生成摘要。

在不同仓库的78任务确认集上，它比批量删除便宜17.7%，但比不删除仍贵2.4%，本地质量非劣也未确立。其固定动作部分省17.4%，剩余部分增加19.8%，恰好抵消。实验中没有运行调用恢复入口，因此不能说“自动按需恢复已被验证有效”。

GLM 的确认实验是正向例外：在 c=0.1 省约16.6%，但 c=0.025 时反而贵7.2%；本地修复率点估计下降3.2个百分点，质量非劣没有成立。它提示长轨迹有空间，并未给出普适方案。

### 8.2 源头截断、窄读取训练、估计重用率

表5在178任务、每条件两次运行中比较：

- 工具输出超过2000字符就保留头1400、尾400：成本在 c=0.1 增加3.6%，步数从51.9增到60.1。
- 用短读取轨迹微调模型：成本增加11.2%，虽通过该实验的质量非劣检验，仍未节省。
- 根据其他轨迹估计观察再利用率：c=0.1 约省0.7%，未建立可靠节省；c=1 约省10.2%，得到支持。

其他尝试也没有被藏起来：只删除能证明过时的输出，固定轨迹节省太少，没有达到在线实验推进门槛；去重长重复块在重放时省钱，真实运行反而涨约4%；统一上下文控制器的多个先导版本没有击败回本规则。

### 8.3 小模型侦察员也要算总账

先用9B模型搜索，再交给27B求解器，确实减少求解器搜索，求解器自身便宜约20%。但把侦察员也计价后，按9/27比例折算，其总费用约降8%，没有建立显著节省；若不折价则涨约15%。该实验没有官方修复评分，不能宣称在相同修复质量下更省。

按需扩展内容读过后再删除的 EDm，在 on-target 上通过±5个百分点等效检验，Verified 成本约降23%；同样没有官方修复结果。保留与编辑相关的代码、LLM重排候选、两块 oracle 证据的组合等附加实验，也没有建立期待中的通用增益。

## 九、六种管理方法一起比较：排行榜随价格变

作者在201任务、三个 Qwen 模型上比较六种方法，共3618次运行，包括不管理、滚动、批量、回本、LLM摘要和反思式管理。每个单元一次运行，额外摘要及反思调用都计入成本。

表2的代表性结论：

- c=0.1 时，Qwen3.6和Coder最便宜的是不管理；Qwen3.8最便宜的是LLM摘要。
- c=1 时，三者最便宜的分别是回本规则、滚动删除、LLM摘要。
- LLM摘要在三个模型、c=0.1 下分别约为+22%、+28%、−19%。
- 反思式管理在相同设置下分别约+36%、+31%、+29%，将额外调用按较便宜模型折价也不能自动反转。
- Qwen3.8 的摘要虽然便宜，官方修复率却下降7.8个百分点。这个质量结果未预注册，且仍受补丁抽取问题限制，但足以阻止“最便宜就是最优”的结论。

这些基线也有实现边界：摘要采用公开 OpenHands 提示，未复现另一研究未公开的修改版本；反思提示按论文描述自写，不能说完全等同原实现。

作者进一步在一个价格区域做联合判断，而非挑一组有利报价。所测33种“方法×模型×框架”组合中，没有一种能在 c=0.025–0.1、p=4–6 整个区域持续更便宜。这个结论不排除个别价格点存在赢家，也不能外推到所有未来方法。

## 十、蒸馏短轨迹：更快提交，也可能更早放弃验证

图10展示另一种路线：不在运行时删除历史，而是让模型学会更短的工作方式。

作者从27B教师的定位轨迹中筛选已提交、编辑到目标、没有格式缺口且成本较低的轨迹。两种证据条件平衡得到464条轨迹，再按生命周期形成696个训练样本。用 LoRA 微调 Qwen3.5-9B，主要参数为 rank=16、alpha=32、两轮训练、最大序列32768，只在助手输出上计算损失；在80个 Verified 任务上比较基础与微调模型。

结果是成本约降32%，少运行9.7步，提交率提高20个百分点。但官方修复收益没有建立稳定改善。图10中，无证据条件从28.8%到33.3%，有证据条件从32.9%到32.1%，后一差值按图中四舍五入约−0.8个百分点。

更重要的是，已提交运行中，首次编辑后的测试/脚本执行次数从4.19降到1.83。没有执行验证就直接提交的比例增加。训练时筛选的是 on-target，未要求真正 resolved，因此作者推测模型可能学到了提前结束，而非真正高效求解；这是一种有证据支持的解释线索，尚未由专门干预证明。

三个预注册的证据交互检验全部未获支持。不能只展示“费用降32%”就将其写成质量保持的成功蒸馏。

## 十一、成本测量本身会制造多大错觉

表7是本文很有实践价值的一部分。

### 11.1 同时跑对照组，可能共享了不该共享的缓存

两个实验条件若使用相同初始提示、同一服务器并发运行，一个条件可能替另一个预热前缀。服务器汇报的缓存命中不全由该运行自己创造。

一个 Verified 证据包实验按服务器命中算只贵8%，按该运行自身可产生的缓存算贵36%；隔离服务器重跑约贵29%。后两者不完全相同，但共同说明前者明显过于乐观。不能把隔离重跑的29%和原批次36%当成同一批数据的精确复算。

作者逐 token 比较本次提示与自身上次提示的最长公共前缀，避免兄弟条件贡献缓存。它仍是理想化的缓存模型，不模拟失效时间、驱逐、缓存写入收费等真实服务细节。

### 11.2 缓存块粒度与聊天模板也重要

旧式块级命中计数会低估真实可复用前缀。某组滚动删除若用旧计数会显示涨价173%，逐 token 核算是116%。结论方向一样，效应大小却差很多。

不同聊天模板会不会保留上一轮完整回复，也会改变可复用量。Qwen3.6的重渲染历史与Coder的逐字保留不同；给Coder额外计入上一回复复用后，滚动删除涨幅从约87%变为98%。这不表示其中一个数字“造假”，而是缓存口径发生了变化，必须写清。

外部真实会话的缓存输入占比与本文实验接近，只能作为合理性检查，不能替代具体供应商的账单验证。

### 11.3 小差异可能只是重复噪声

成本均值的相对标准误约3%–4%，两次评估的成本能相差4%–5%；同一智能体两次质量评估能差约1.6个百分点。报告几百分点的节省或质量提高时，必须同时看配对区间、重复数和任务分母。

## 十二、如何评价这篇论文

### 值得借鉴的贡献

第一，它把“上下文长度、探索行为、缓存费用、最终质量”分成了不同结果变量，避免用一个代理指标代替全部结论。

第二，它展示了固定动作重放和在线重跑的差距。对动态系统来说，算法修改信息后，模型可能改变行为，这部分往往比静态压缩率更重要。

第三，它公开了大量失败的预期，包括证据协同、关系保留、窄读取、价格交叉点预测和部分蒸馏交互。新任务与新框架的确认实验也没有被替换成只保留成功批次。

### 仍不能越过的边界

- 缓存价格模型理想化，未包含所有服务器和非模型运行成本。
- 修复评分补丁抽取不完整，部分小幅质量结论需要重算。
- 若干先导实验选择与内部预注册存在先后顺序限制。
- 任务、可执行环境和模型格式不完全一致，跨框架差异有多个来源。
- 核算分解不是完整因果识别，行为残差也包含运行随机性。
- 检索定位提升不能转述成修复提升，未显著不能转述成证明没有效果。

## 十三、与当前 causal-review / Seer 的关系

以下结合最新研究记录，区分已有事实和可借鉴建议，不在此启动新实验。

**已有事实：**RQ3当前按38个不同可见任务统计，重复组取冻结顺序第一条；这与RQ1/RQ2原始52例不是同一批任务。CoSIL的主要调用消耗集中在检索/裁剪阶段，直接与筛选裁决的额外几次调用不能代表全链路成本。LocAgent的曝光记录修复涉及真实返回内容与模型后续反馈，也不能仅补一个台账就视为协议已恢复。SweRank的候选排序、完整函数预算和实际交付顺序同样需要区分。

**本文真正补充的视角：**CPI研究关心哪些上下文对定位有帮助或产生干扰；本文主要研究添加或撤回内容后，缓存计价和后续行为如何共同改变成本。前者的语义角色干预与后者的生命周期管理不是同一个问题，但可以用同一份严谨曝光和费用记录衔接。

**建议，尚未由本文或当前项目自动实现：**

1. 每条任务分别保留主方法、筛选器、裁决器的未缓存输入、缓存输入、输出及调用次数。不要只给筛选后 prompt 长度。
2. 把固定曝光下的直接/筛选裁决，与允许继续搜索的闭环策略分开。后者可能重新获取被删证据，估计的效应已经改变。
3. 同一任务固定基线排序和真实交付内容，记录预算截断后的候选，不能把检索命中与模型实际看到混为一谈。
4. 若比较价格，先在当前38任务的既有记录上按统一口径核算，再讨论是否需要新增实验。小幅收益需同时报告配对不确定性与失败任务，避免按成功运行筛选样本。
5. 论文中的固定动作重放可作为成本审计思路，但若要论证“删除P通过改变搜索导致质量变化”，仍需要真实执行干预和独立的识别设计，不能直接引用核算恒等式代替证明。

一句话收束：**上下文优化要同时回答“模型看到了什么、接下来做了什么、系统为此付了多少、最终解决了什么”。短提示只是其中一个中间状态。**
