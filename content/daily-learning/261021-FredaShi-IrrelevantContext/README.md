## 一句话先说清：模型会做题，不等于它知道哪些信息不该用

设想一道小学应用题：

> Jessica 比 Claire 大 6 岁。两年后 Claire 20 岁。Jessica 现在几岁？

答案是 24。现在只加一句：

> 20 年前，Claire 父亲的年龄是 Jessica 年龄的 3 倍。

这句话听起来和人物、年龄都很相关，却对原问题没有帮助。正确答案仍然是 24。如果模型因为这句话改了答案，问题就不在算术能力，而在于它**没有稳定地区分“看起来相关”与“解决问题所必需”**。

这正是本文的故事。过去的数学推理基准通常把需要的信息整齐地放进题面，模型只需“使用信息”；真实任务却要求先判断什么该用、什么不该用。作者因此不再一味增加题目难度，而是固定一批模型本来能解的题，只插入一句不会改变答案的干扰信息，观察模型是否仍能保持原来的判断。

### 对当前研究的直接价值

当前仓库定位研究正在把输入拆成核心证据（C）、看似合理但未必关键的信息（P）和无关信息（I），并计划用配对干预区分 P 的帮助与干扰。本文最值得借鉴的不是“无关信息有害”这句常识，而是三点实验设计：

1. **先固定 clean task**：只在模型原本能解决的题上研究干扰，避免把“模型本来就不会”误判成“被上下文干扰”。
2. **每次只改变上下文，不改变正确答案**：干预前后共享同一目标，结果差异才更接近上下文的因果效应。
3. **同时报告单次平均表现与跨干扰变体的一致性**：偶尔答对不能说明稳健；同一任务换几种干扰就崩，才是更真实的脆弱性。

但它只能作为**机制先例**：数学题里人工模板生成的一句话，和真实仓库中的调用者、测试、文档、包装函数不是同一种对象。本文没有证明代码 Agent 中的 P 或 I 一定产生同样效应。

## 核心办法：把同一道题复制很多份，每份只换一条“没用但像有用”的信息

### 第一步：挑 100 道模型至少会一种解法的题

作者从 GSM8K 训练集随机抽 1,000 道题作为开发集，再选出 100 道“至少被一种待测 prompting 方法正确解决”的题作为 base set。每道题需要 2–7 个推理步骤，其中 60 道只需两步。

这个筛选很关键。论文问的不是模型总体数学水平，而是：**对一项已经表现出能力的任务，仅加入无关信息，会不会把能力破坏掉？** 如果 base 题本来就做错，加入干扰后仍做错，无法识别干扰的作用。

代价是，这 100 道题是一个偏容易且经过模型表现筛选的子集，不能代表完整 GSM8K 难度分布；后面会回到这个选择偏差。

### 第二步：沿三个轴生成干扰句

作者给每道 base 题增加一句信息，并用三个因素控制它“有多像相关信息”：

| 干预因素 | 两个水平 | 直观含义 |
|---|---|---|
| Topic | in-topic / off-topic | 干扰句是否谈同一主题，例如都谈年龄或钱 |
| Role overlap | overlap / no overlap | 是否复用原题人物，或写成“Jessica 的父亲”等关联角色 |
| Number range | in-range / out-of-range | 干扰数字是否和原题数字数量级相近 |

例如原题谈 Claire 和 Jessica 的年龄，最迷惑的干扰通常也是年龄主题、带 Claire 亲属、数字又与原题相近。作者为每道题写 in-topic 和 off-topic 模板，再填充人物与数字。所有生成句都经人工检查：英文表达必须可接受，且加入后不得改变标准答案。如果代词产生歧义，作者会改写问题以保留原义。

三个轴组合后，完整 GSM-IC 有 58,052 个派生样本。考虑 API 成本，主实验从中均匀抽取 4,000 个样本（GSM-IC-4K），覆盖全部 100 道 base 题。

### 第三步：用三种指标区分“平均能做”与“稳定不受骗”

作者没有只报普通准确率。

- **Micro accuracy**：把 4,000 个派生题逐题平均。它回答“随机给一种干扰，平均答对多少”。
- **Macro accuracy**：对每道 base 题，只有它的所有干扰变体都答对才算这一题通过。它回答“换成不同干扰句后，这道题是否始终稳定”。
- **Normalized accuracy**：用带干扰准确率除以相同方法在 clean base 上的准确率。它把“原本数学能力不同”从干扰损失中部分剥离。

这里的 macro 和常见的“按类别平均准确率”不同。它是一个很严格的 all-variants-correct 指标。假如一道原题有 40 个干扰版本，答对 39 个，micro 会很高，但该 base 题的 macro 仍记为失败。正因如此，micro 与 macro 的巨大差距揭示了“平均看起来不错，但行为不稳定”。

## 作者比较了什么：四类推理方式，三种缓解思路

主模型是当时的 `code-davinci-002`，并用更偏指令跟随的 `text-davinci-003` 补充验证。论文比较：

- **Chain-of-Thought（CoT）**：用一个示例展示逐步推理。
- **Zero-shot CoT（0-CoT）**：不给示例，只加 “Let’s think step by step”。
- **Least-to-Most（LtM）**：先把大问题拆成子问题，再按顺序解决。
- **Program prompting**：让模型生成 Python 程序，并由解释器执行得到答案。

缓解手段有三类：

1. **Self-Consistency（SC）**：温度 0.7 采样 20 条推理路径，对最终答案多数投票；普通实验则用温度 0 的 greedy decoding。
2. **带干扰的示例**：prompt 示例也加入一条无关信息，并在解答中示范忽略它。
3. **显式指令**：在 prompt 前写“可以忽略问题中的无关信息”。

整体实验可以压缩为一句话：**固定原题、正确答案和模型，系统改变测试题的干扰、示例是否带干扰、是否给忽略指令以及解码方式，再观察准确率和跨变体稳定性。**

## 结果一：加一句无关信息，所有方法都会退化

Table 3 是全文最重要的表。先看 `code-davinci-002`、不带干扰的示例、greedy decoding：

| 方法 | clean base 准确率 | GSM-IC micro | normalized micro | GSM-IC macro |
|---|---:|---:|---:|---:|
| CoT | 95.0 | 72.4 | 76.2 | 6.0 |
| 0-CoT | 44.0 | 29.0 | 65.9 | 1.0 |
| LtM | 94.0 | 77.5 | 82.4 | 18.0 |
| Program | 83.0 | 54.4 | 65.5 | 5.0 |

读表时要分两步。

第一，micro 明显低于 clean base：CoT 从 95.0 降到 72.4，LtM 从 94.0 降到 77.5，Program 从 83.0 降到 54.4。一句话确实可以破坏本来正确的推理。

第二，macro 远低于 micro。CoT 平均还能答对 72.4% 的干扰题，但只有 6% 的 base 题能在所有干扰变体下保持正确；LtM 最好，也只有 18%。这说明问题不是“每题都稳定下降一点”，而是同一道题会随着干扰句外观改变而反复翻转。

论文中一个很直观的失败例是银行余额：Lucy 原有 65 美元，存 15、取 4，答案应为 76。加入“Lucy 母亲月租 10 美元”后，CoT、LtM 和 Program 都把这 10 美元减掉，统一答成 66。模型生成了形式完整、步骤流畅的推理，但把不该进入计算的数字纳入了状态。

**Takeaway：** clean accuracy 衡量“会不会做题”，带干扰的 macro 更接近“是否真正识别了必要信息”。两者不是同一个能力。

## 结果二：什么样的无关信息最危险？“像真的”比数字大小更重要

作者在 Table 4 按三个生成因素分解表现。以 `code-davinci-002 + CoT` 为例：

| 干扰类型 | micro accuracy | macro accuracy |
|---|---:|---:|
| 同主题 | 63.1 | 10.2 |
| 不同主题 | 80.7 | 33.0 |
| 角色名重叠 | 68.3 | 10.3 |
| 不重叠 | 76.6 | 22.2 |
| 数值同范围 | 70.2 | 11.0 |
| 数值不同范围 | 74.6 | 19.0 |

同主题相较不同主题，micro 低 17.6 个百分点；复用人物或其亲属，也明显更容易诱使模型把干扰纳入推理。数字范围的影响相对小，某些设置还有反常方向。

这对“P 与 I”很重要：**真正危险的可能不是明显无关的 I，而是语义上贴近任务、具有相同实体和相似数值结构的 plausible distractor。** 但论文没有把这种句子标成“部分有用信息”；其 ground truth 仍然是完全无关。把这个发现迁移到代码时，应把“语义相似性”和“真实因果/功能相关性”分开标注。

Figure 4 还显示：当题目需要 4 步以上推理时，CoT 与 Program 的准确率明显下降，而 LtM 相对稳定。作者据此认为，先拆分子问题可能帮助模型隔离相关信息。不过这是方法与任务交互的经验结果，不是对内部注意机制的直接证明。

**Takeaway：** 干扰强度不是一个单轴 token 数问题；主题、实体重叠、任务难度和推理策略会交互。

## 结果三：三种缓解方式都有效，但没有真正解决问题

### 显式说“忽略无关信息”

对 `code-davinci-002 + CoT`，加指令后 micro 从 72.4 升到 77.8，macro 从 6.0 升到 15.0；LtM 的 micro 从 77.5 升到 80.6，macro 从 18.0 升到 25.0。作者额外检查发现，只写“解决小学数学题”没有同样收益，真正起作用的是明确的忽略指令。

这说明模型可以被提示改变筛选行为，但“能听懂提醒”不等于已经稳健：最好的 instructed macro 仍只有 25%。

### 在示例中演示如何忽略

把 prompt 的单个示例也改成“带干扰题 + 正确忽略干扰的解法”，CoT micro 从 72.4 升到 76.8，LtM 从 77.5 升到 80.7；相应 macro 从 6.0 升到 14.0、从 18.0 升到 28.0。Table 5 显示，这种示范没有明显损害 clean GSM8K 或 SVAMP 表现。

这里不能直接写成“训练模型学会筛选”：权重没有更新，只是 in-context exemplar 改变了当次生成分布。结果支持的是“示范有帮助”，不是“模型形成了可泛化的相关性概念”。

### 多采样再投票

Self-Consistency 的提升最大。20 次采样后：

| 方法 | greedy micro | SC micro | SC macro |
|---|---:|---:|---:|
| CoT | 72.4 | 88.1 | 30.0 |
| 0-CoT | 29.0 | 64.3 | 1.0 |
| LtM | 77.5 | 93.4 | 45.0 |
| Program | 54.4 | 74.6 | 13.0 |

对 CoT 和 LtM，20 个样本中至少一个包含正确答案的 recall 达到 99.7%；但最终多数投票的最佳 macro 仍只有 45%。也就是说，模型几乎总能“想到”正确路径，却经常不能让正确路径成为稳定多数。

这一区分很有价值：检索/上下文实验也应分别报告“正确目标是否曾出现”和“最终是否稳定选择”，不能把候选 recall 当最终判断能力。

**Takeaway：** 重采样能显著提高平均正确率，却没有消除跨干扰变体的不稳定，而且成本是每题 20 次生成。

## 结果四：更多示例在 clean set 更强，在干扰条件反而可能更脆

作者将 1-shot CoT 与此前在 GSM8K 上表现更好的 4-shot CoT 对比：

| Prompt | GSM8K clean | GSM-IC 两步题 | GSM-IC 多于两步 |
|---|---:|---:|---:|
| 1 个示例 | 60.3 | 73.6 | 70.8 |
| 4 个示例 | 66.3 | 78.0 | 69.4 |
| 1 个示例 + 忽略指令 | 58.8 | 79.0 | 76.0 |
| 4 个示例 + 忽略指令 | 66.5 | 79.2 | 70.6 |

更多示例让 clean GSM8K 提高 6 个点，却在复杂的干扰题上下降；加忽略指令后，1-shot 在复杂题上甚至领先 4-shot 5.4 点。作者称这可能是更复杂 prompt 导致 overfitting。

“overfitting”在这里更像解释而非被独立验证的机制。四个示例不仅数量更多，示例难度和内容也不同，token 长度同样变化，论文没有把这些因素完全拆开。因此更稳妥的结论是：**clean-set 上更强的 prompt 不保证在带干扰条件下更稳健。**

## 结果五：在自然长文本 DROP 中，提醒也有小幅收益

GSM-IC 的干扰是模板生成的。为测试更自然的场景，作者又在 DROP 的 football 子集上比较 CoT、LtM 以及它们的 instructed 版本。DROP 给出包含大量无关比赛事件的长段落，再要求做离散推理。

| 方法 | code-davinci-002 | text-davinci-003 |
|---|---:|---:|
| CoT | 67.4 | 68.2 |
| CoT + instruction | 68.9 | 69.9 |
| LtM | 73.4 | 70.2 |
| LtM + instruction | 74.4 | 72.8 |

四组都提高 1.0–2.6 个点，方向一致但幅度远小于 GSM-IC。论文没有报告显著性或置信区间，因此这里最多支持“在一个自然长文本子集上也观察到一致的小幅增益”，不能宣称普遍有效。

## 证据审查：这篇论文证明了什么，也遗漏了什么

### 证据较强的部分

1. 在所测两个 2022 年代模型、100 个经过筛选的 GSM8K base 题和 4,000 个干扰变体上，单句无关信息会显著降低多种 prompting 方法的表现。
2. 同主题、实体重叠的干扰通常更危险，说明表面相关性是一个重要异质性因素。
3. 带干扰示例、显式忽略指令和 Self-Consistency 都能缓解平均性能下降；其中多采样提升最大。
4. average accuracy 与 all-variants consistency 揭示不同构念；只报前者会遮住行为不稳定。

### 不能从论文推出的部分

1. **不是现代模型结论。** `code-davinci-002` 与 `text-davinci-003` 已不代表 2026 年模型、长上下文或工具型 Agent。
2. **不是代码仓库结论。** 一句数学题干扰与跨文件代码、测试、文档、调用图信息在结构和可验证性上差异很大。
3. **不是完整因果机制解释。** 输入干预对输出的效应识别较干净，但论文没有观察注意力、内部状态或工具轨迹，不能说明模型究竟为何受骗。
4. **容易子集限制外推。** base 题先按“至少一种方法能答对”筛选，估计的是 conditional robustness，而非随机真实任务上的总体效应。
5. **干扰组合不是完全现实分布。** 模板因素虽便于控制，但各 base 题生成变体数和自然度可能不同；macro 的 all-or-nothing 也会随变体数量改变严格程度。
6. **缓解比较未完全等成本。** SC 用 20 次生成，显著增加推理成本；4-shot 对比也同时改变 prompt 长度与示例组成。
7. **统计不确定性不足。** 关键表主要给点估计，没有系统置信区间、配对效应分布或多重比较控制。

## 对当前 C/P/I 与仓库定位实验的可执行迁移

### 1. 把“先筛 clean success”写进估计目标

可以仿照本文，把任务分成两层：

- **总体层**：所有 15 个案例上报告实际成功率，保持生态有效性。
- **机制层**：只在统一 EvidenceLoc head 的 clean Core 条件下稳定成功的案例上，估计追加 P 或匹配 I 后的 paired effect。

第二层不是把失败例藏掉，而是在明确回答条件问题：`在核心证据已经足以成功时，增加某类上下文会怎样改变结果？` 需同时报告筛选前后分母，不能把 conditional effect 写成总体效果。

### 2. P 与 I 的匹配不能只控制 token 数

GSM-IC 表明主题与实体重叠比纯数字范围更影响干扰。因此 P→I 配对除 tokens、节点数、位置外，还应至少记录：

- 与 issue/CWE 的语义相似度；
- 是否共享函数名、类型名、文件前缀或调用实体；
- 距 Core 的图距离与目录距离；
- 是否含与答案相近但不充分的术语或分支条件。

否则“P 比 I 更有帮助”可能只是 P 更像题面，而不是它包含真实支持证据。

### 3. 增加一致性指标，不只报一次节点 F1

本文 macro 的思想可转成：对同一 case 的若干匹配干预变体，只有全部保持 Core 选择或正确节点集合才记为 robust。建议同时报告：

- 平均节点 Precision / Recall / F1；
- 任一运行命中目标的 candidate recall；
- 多次固定输入的 selection stability；
- 跨 P/I 变体的 all-variants success；
- 结果翻转率及翻转方向（成功→失败、失败→成功）。

这能区分“正确答案偶尔在轨迹中出现”与“Agent 能稳定把它作为最终诊断”。

### 4. 因子化干预，而不是把所有 P 混成一类

可把 P/I 进一步描述为三个近似正交的因素：功能主题相似度、代码实体重叠、结构距离，再用小规模析因或分层配对检查交互。当前只有 15 例，不宜追求大而全显著性；先报告逐例 paired transitions 与效应异质性，比给一个不稳的总体均值更诚实。

### 5. 把“显式忽略指令”作为诊断条件而非默认主方法

可以设置一个轻量诊断：相同上下文下，一组只要求定位，另一组明确提醒“并非所有提供的上下文都相关，请只选择对漏洞机制必要的节点”。如果后者显著减少误选，说明失败至少部分来自选择策略；如果不变，可能是模型无法区分相关性。但该 prompt 同时改变任务定义，不应与原方法混在一个主榜单。

## 最后记住六件事

1. 会解 clean task 与会过滤上下文是两种能力。
2. 最危险的干扰往往不是明显噪声，而是主题和实体都很像答案的“伪相关”信息。
3. 平均准确率可能掩盖同一任务在不同干扰变体下频繁翻转；一致性应单独度量。
4. 示例、指令和多采样都能缓解干扰，但没有在本文中消除问题。
5. clean-set 最强的 prompt 不必然最稳健；成本、长度和示例组成必须共同控制。
6. 对仓库级 Agent，这篇论文提供的是配对干预与指标设计的机制先例，不是现实代码场景的直接证据。
