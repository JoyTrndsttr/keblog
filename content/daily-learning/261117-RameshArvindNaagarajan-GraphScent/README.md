## 一、看到一段“相关代码”以后，下一步该往哪里走？

一个函数看起来很符合错误描述，却没有需要修改的语句。它可能只是调用了真正出错的函数，也可能是一个所有地方都会使用的通用工具。对于只能再读十几段代码的智能体，这两种“相关”值得走向完全不同的下一步。

传统图搜索常把读到的相关性向邻居扩散。但代码调用图有方向：入口调用业务逻辑，业务逻辑再调用格式化、检查或转换工具。把一个高分均匀发给所有邻居，很可能把有限预算消耗在这些常见工具上。

GraphScent 把这个问题转成了可测对象：**当模型单独阅读一段没有被参考补丁修改的代码时，它给出的相关性分数，能否提示附近存在真正的修改目标？这种提示能力是否取决于关系方向？**

这比“图方法是否比文本检索好”更具体。它研究的是图上的证据如何传递，也正好接近 CPI 所关心的区别：看起来合理、与任务路径有关、以及足以指导最终定位的内容，可能发挥不同作用。

[作者主页](https://ramesh-arvind.github.io/)介绍，Ramesh Arvind Naagarajan 是开姆尼茨工业大学自动控制与系统动力学方向的博士研究人员，所在团队由 Stefan Streif 带领；[学校团队页](https://www.tu-chemnitz.de/etit/control/team/index.php.en)可核对其身份。他此前的研究主要在可解释控制、语言接口与因果推理，包括温室控制的自然语言解释，以及其个人发表列表所列的 ICML 2026 工作 *Hierarchical Causal Abduction: A Foundation Framework for Explainable Model Predictive Control*。这是一条控制系统与解释性研究背景，不应包装成长期软件定位团队的系列成果。[作者发表列表](https://ramesh-arvind.github.io/publications/)

本文单独提出并评估 GraphScent，没有沿用 CoSIL 或 LocAgent 的名称冒充其复现。它承认有向异构代码图已有丰富先例，将贡献放在三个更窄的点上：测量方向性相关信号，按模型与关系校准信号，检查这些选择在有界搜索中是否有效。

读它的主要价值也在这里：它有结构控制、失败结果和方法消融，而不只是一个新框架的总体分数。同时它仍是新预印本，公开工件与正文存在需要对齐的部分。下面先完整重建论文，再集中检查证据边界。

## 三、用一个小例子串起来：入口提供线索，底层工具可能只增加岔路

作者公开 Notebook 的教学演示构造了一个小仓库：`api.handle_request` 使用 `SyncEngine.parse_token`，后者调用 `low_level_trim`；另有 `AsyncEngine.parse_token` 作为平行实现。请求涉及带冒号前缀的 token 处理。

这只是作者的工具演示，**不是论文中某个真实任务的成功轨迹**。我们用它理解三种关系：

- 相对 `parse_token`，`handle_request` 是上游调用者，关系记作 `called_by`。
- 相对 `parse_token`，`low_level_trim` 是下游被调用者，关系记作 `calls`。
- `SyncEngine` 是包含该方法的作用域，记作 `parent`。

如果模型看到 `handle_request`，判断它与报错路径有关，搜索器可以增加其被调用函数 `parse_token` 的优先级。这里“测量时称 called_by”和“搜索时沿 caller → callee 传播”是一回事：前者从未知目标看邻居，后者从已读线索走向候选目标。把这两个视角弄反，会把全文的方向性结论读反。

如果模型只看见 `low_level_trim`，它可能像一个行为正常的通用工具，难以提示是谁用错了它。作者认为这种功能角色差异会反映在打分分布里，于是先测量，再设计搜索策略。

## 四、先把评测对象说清：211 个任务，来自两个不重叠的仓库组

### 4.1 论文定位的是实体，不是整个补丁

目标实体是既有的 Python 函数、方法或类。参考补丁修改到的这些实体组成目标集合。搜索过程最后挑选一个主要修改实体，检查它是否属于目标集合。

这与文件级 F1、修复成功率不同。一个任务可能有多个需要修改的位置，命中其中一个实体，不等于找齐全部改动，更不等于测试通过。

作者从两个来源构造样本：

| 来源 | 原始任务 | 可映射定位任务 | 仓库数 |
|---|---:|---:|---:|
| 公开竞赛集 | 129 | 113 | 4 |
| 2025–2026 补充集 | 102 | 98 | 82 |
| 合计 | 231 | 211 | 86 |

公开集的 113 条来自 fastapi 56 条、rich 44 条、requests 12 条及 httpx 1 条。排除的 16 条中，13 条只修改模块顶层语句或新增既有定义之外的符号，另外 3 条仅涉及文档、测试或非 Python 文件。

补充集最初覆盖 84 个仓库，按相同实体映射规则排除 4 条后，剩下 82 个仓库、98 条任务。这一组与公开集仓库完全不重叠，时间介于 2025-01-02 与 2026-05-11。排除规则发生在评测之前，但会限定结论适用范围：只修改模块顶层代码或需要新增实体的任务，没有被本文主实验覆盖。

### 4.2 新时间段不等于模型一定没见过

作者额外做了一个零源码探测：只给仓库名和 issue，让模型猜最多五个缺陷文件路径，再按 issue 是否明示金标准文件名分层。

对未明示文件名的请求，31B 在公开集的路径命中率为 38.7%，补充集降到 11.1%；E4B 为 8.4% → 3.2%，12B 为 19.3% → 9.5%。它提示新仓库上的先验可用性较低，实际搜索更重要。

这项探测统计的是原始 129/102 条的文件命中，不应与实体定位的 113/98 条混用。文件路径也可能由命名惯例推断，故此处测到的是“不给源码时能猜对多少”，并非纯粹测量训练记忆。作者自己也明确承认，模型未公开逐提交训练边界，时间划分不能保证无预训练暴露。

## 五、第一件意外的事：现成调用图连方向都可能没有保住

论文没有直接把“图搜索不好”归因于模型，先审计了竞赛提供的调用图。

去掉自环与重复记录后，457,324 条有向边恰好对应 228,662 个无序节点对，每个节点对都同时存了两个方向，且统一标作 `calls`。因此这份图无法区分谁调用谁。另有 27.3% 的非测试候选实体是孤立节点，fastapi 中达到 44.3%，与装饰器注册路由等难以用显式调用解析覆盖的结构有关。

图 1 的左侧说明了后果：从 issue 提及的锚点出发，39/113 个任务不可达；从词面检索 BM25（Best Matching 25）排名前五的种子出发，仍有 8/113 个不可达。在旧候选表示上，个性化 PageRank 把平均倒数排名从 BM25 的 0.174 降到了 0.083。

于是作者运行时用 Python 标准库 `ast` 重建带类型的抽象语法树（Abstract Syntax Tree，AST）多重图。这里的“运行时”指现场解析仓库，**不是执行程序并采集动态调用轨迹**。

图包含模块、类、函数与方法，保留四类结构：包含及同级关系、仓库内可解析的调用、继承、平行方法覆盖。调用解析处理部分 `self`/`cls` 调用、导入别名与无歧义同名符号；这是一种轻量静态近似。构建和 BM25 索引在作者 CPU 上中位耗时 0.17 秒，P90 为 1.48 秒，最大 7.94 秒。

加上包含边后，全部候选都有图连接；只计调用、继承和覆盖等非包含边，两个数据组的连接率约为 83.4% 与 83.7%。公开集 92/113 个任务的目标距 BM25 前五种子不超过两条无向边，四跳内达到全部任务。

但“连得到”仍不等于“知道往哪走”。表 2 在相同新图与折叠视图上给出的静态控制如下：

| 无模型调用的检索方式 | R@5 | MRR |
|---|---:|---:|
| BM25 | 46.5% | 0.357 |
| 无向 Typed-AST PageRank | 38.9% | 0.268 |
| 有向 Typed-AST PageRank | 33.6% | 0.205 |
| BM25 + 有向 PageRank 融合 | 45.5% | 0.351 |

R@5 表示前五名是否命中目标；平均倒数排名（Mean Reciprocal Rank，MRR）看第一个正确目标排得多靠前。修好图以后，纯中心性传播仍未胜过词面检索。由此得到本文下一步的动机：图关系需要与当前请求下的内容判断结合。这是对所测试排序器的结论，不能扩张成所有静态图方法永远无效。

## 六、如何测量一段未改代码有没有“带路能力”？

### 6.1 让模型每次只看一个有界视图

每个函数、方法或类最多展示 60 行。短函数直接展示，长函数保留签名、装饰器、文档串、控制流、调用与返回等结构；长类折叠为类说明、类属性和方法头。每次调用只看 issue 与当前实体，不带前面阅读的会话历史。

冻结的 Gemma 4 在温度 0、关闭 thinking 的条件下输出四档分数：

- 3：需要修改的缺陷直接位于当前实体。
- 2：高度相关，或是缺陷的直接调用者、包含作用域。
- 1：在较宽泛执行路径上，或是松散相关模块，预计不会被修改。
- 0：与请求无关。

这套量表本身已经把“直接修改目标”和“可以带路的上下文”分开。它还明确提到 caller 与 enclosing scope，后文解读方向性时必须记住这一提示条件。

### 6.2 用结构邻居对比难词面干扰项

离线分析中，作者知道参考修改集合，因此能采样它的未改动父作用域、上游调用者、下游被调用者、同级方法等。对照不是随便挑的无关函数，而是 BM25 排名靠前、并且距目标至少三条无向图边的非金标准候选。

作者把关系 r 的 scent 定义为：随机抽一个这种关系的邻居和一个远处词面干扰项，前者得分更高的概率；平分时各算一半。这个量等价于两组分数的受试者工作特征曲线下面积（Area Under the Receiver Operating Characteristic Curve，AUROC）：

`Scent(r) = P(S(邻居) > S(干扰项)) + 0.5 × P(S(邻居) = S(干扰项))`

0.5 表示在这个样本定义下没有分辨力，超过 0.5 表示邻居分数通常更高。它衡量的是分数的诊断性，既不是目标命中率，也不是某段代码加入上下文后的因果效应。

### 6.3 方向不对称出现在哪里？

表 3 与图 2 给出 211 条任务的合并结果，置信区间使用 1,000 次按任务聚类的 bootstrap。以下选取最决定结论的关系：

| 邻居相对目标的关系 | E4B | 12B | 31B |
|---|---:|---:|---:|
| parent：包含作用域 | 0.643 | 0.713 | 0.719 |
| called_by：上游调用者 | 0.600 | 0.641 | 0.623 |
| calls：下游被调用者 | 0.477 | 0.483 | 0.487 |
| sibling：同级方法 | 0.519 | 0.513 | 0.506 |

父作用域与上游调用者稳定提供正向信号；下游被调用者接近随机基线。同级方法也没有明显信号。继承与覆盖关系样本较少，区间较宽，例如继承只有 22 个采样节点，不能仅凭某个点估计较高就得出稳定优势。

在公开集上，历史共同修改关系的 scent 为 0.463–0.498，竞赛 256 维嵌入近邻为 0.436–0.470，另测的 Qwen3-Embedding-0.6B 近邻为 0.541–0.565。后者有些信号，但弱于 parent 与 called_by。这组结果限制了一个常见直觉：结构靠近、语义靠近和历史一起改过，不能自动相互替代。

图 2 还分开画了两个仓库组。31B 的 parent 从公开组 0.696 到补充组 0.775，called_by 从 0.651 到 0.587；下游 calls 为 0.478 与 0.507。方向性并非只由四个老仓库撑起来，但效应大小会随仓库组变化。

## 七、先排除两个简单解释：父类偷偷展示答案了吗？调用者只是更像 issue 吗？

### 7.1 遮掉目标方法，父作用域信号还在

一个短类的完整视图可能直接包含有缺陷的方法体。作者对 187 个父节点做两种变换：只遮掉所有 gold 子方法的代码行；或者删除所有方法体，只保留类签名、类说明与非 gold 方法头。

以 31B 为例，原始 parent 的 AUROC 为 0.719，遮掉 gold 方法后为 0.700，进一步只保留头部与说明时为 0.728。12B 分别为 0.713、0.700、0.716。长类本来就骨架化的子集也仍有明显信号。

因此父作用域的提示能力不会随着目标方法体消失而消失。论文称此为 zero-leakage control，更准确的范围是排除了“视图直接包含目标代码行”这一来源，尚未穷尽所有可能的语义提示或预训练暴露。

这里使用 gold 来决定遮掉什么，属于离线机制控制，不能在部署时假装已知应该遮哪段代码。

### 7.2 控制词面相似度、长度与源码重叠

远处干扰项的归一化 BM25 平均分为 0.634，上游调用者只有 0.308；平均长度分别为 38.5 与 38.7 行。调用者并没有占到“文本更像、代码更长”的便宜。

进一步只保留与目标源码范围没有重叠的 297 个调用者与 372 个被调用者，直接比较两组分数，E4B、12B、31B 的 AUROC 分别为 0.630、0.652、0.629。再用回归同时控制 BM25 与片段长度，调用者指示变量的系数仍为正：+0.471、+0.344、+0.221，95% 区间均在零以上。

附录还按词面相似度分层。低、中、高三个区间内，调用者对被调用者的点估计都大于 0.55，但部分区间置信区间跨过 0.5，因此“每一层都显著成立”会过度解读。

作者给出的功能解释是：调用者更容易呈现用户症状的入口与委派关系，下游通用函数单独看通常行为自洽。现有控制让这个解释更可信；它仍未完成对所有功能角色、提示词和任务机制的因果识别。

## 八、为什么不能直接把 3 分当作最强证据？

不同模型打分习惯差别很大。在公开集的远处干扰项中，E4B 给 3 分的比例为 **50.9%**，12B 为 17.4%，31B 为 9.6%。E4B 经常把错误候选说得很确定。

但 E4B 并非完全没用。它给真实上游调用者 0 分的比例只有 6.6%，给远处干扰项 0 分的比例为 28.2%。所以关键可能是“很少明确排除”，而非“经常给最高分”。

GraphScent 使用关系条件下的对数似然比，英文 Log-Likelihood Ratio，简称 LLR。直觉是问：这个分数出现在真实关系邻居上的频率，相对出现在干扰项上的频率高了多少？

`ℓ_r(s) = log [ P_cal(S=s | 关系r) / P_cal(S=s | far) ]`

概率由校准数据计数并加 Laplace 平滑，防止某档零计数产生无穷大。比值大于一，就增加对应候选的证据；小于一，就减少。

在 E4B 的公开组校准表中，调用者得 3 分只对应 +0.26 的更新，得 2 分反而对应 +0.69，得 0 分对应 −1.39。原始量表是有序的，但**证据强度不必随原始分数单调增加**。这就是校准与简单乘一个固定权重的根本区别。

校准分两种方式：公开集采用留一仓库外推，用其他仓库的数据拟合当前仓库的表；补充集直接使用整个公开集拟合并冻结的表。部署搜索本身不读取测试任务的 gold 邻居标签。所谓 training-free 指没有更新语言模型权重，仍然使用了有标签的离线校准信息。

## 九、GraphScent 如何完成一次定位？

图 3 的流程可以理解成“词面先验 → 小块观察 → 外部信念更新 → 一次并排决策”。本文先按论文公式与附录 A 讲解；发布代码与公式的差异将在工件审查中说明。

### 9.1 先用词面检索建立起点

对 issue 与折叠代码视图计算 BM25，归一化后乘以 α=3，作为每个候选的初始分数。BM25 前三个原始种子在前三次探测中得到保障，避免图传播从一开始就完全覆盖掉直接词面线索。

### 9.2 只让有诊断力的关系传播

校准集上 scent 达到 τ=0.55 的关系被纳入传播集合。默认主要保留 parent 与 called_by，部分模型或划分还保留继承、覆盖。传播时从已读父作用域走向子实体，从已读调用者走向被调用的候选目标。

这里“排除 calls”是排除**读了目标下游工具后，反过来推高其上游**的那类低信号通道，不能误解为禁用所有 caller → callee 的调用边。

为什么选 0.55？作者在 40 个公开任务图上做了 12×12 组配置、合计 5,760 次线性传播模拟，横轴改变直接目标判别能力，纵轴改变邻居信号强度。图 4(a) 显示，在实际模型约 0.65–0.74 的目标判别范围内，沿 scent 不高于 0.52 的边扩散，困难目标发现率可能下降约 15 个百分点；限制到更强信号关系后才有净收益。阈值是这一模拟与数据条件下的设计依据，不是所有代码图通用的常数。

### 9.3 读取一次，更新自己和指向的候选

每次选一个未访问实体，获得 0–3 分后，在外部状态中加入自身证据与关系 LLR。图中连接很多候选的信号会按度数平方根衰减，减少大范围扩散。还允许从“调用某个类的节点”经该类走到其方法的半权重两跳通路。

下一次选择综合当前信念与探索奖励：

`a(v) = b(v) + c / √(1+n_vis(v))，c=0.35`

其中 b 是累计信念，n_vis 是附录所说的邻居访问计数。虽然候选自身还没读过，它的邻居可能已被多次探测；这个奖励使搜索不只反复挤在被覆盖很多次的区域。

每次模型调用都重新开始，不携带历史对话；记忆由控制器的数值状态保存。主要预算 B=24，另测 B=15。这控制的是探测次数与单次上下文，不意味着所有方法逐任务 token 完全相同。

### 9.4 最后让六个候选并排竞争

四档评分会产生许多平分。24 次读取结束后，搜索器把已访问实体按信念排序，取前六个折叠视图，再进行一次独立调用，让模型选择主要修改实体。

这个 listwise 步骤增加了候选间比较信息，和逐个打分后直接取最大值不同。最终一共至多 24 次单节点探测加 1 次终选，输出是一个实体。

## 十、实验如何分清“找到过”“保住了”“最后选对了”？

作者在 Gemma 4 E4B、12B、31B 三个规模上，用相同折叠视图、温度 0 与关闭 thinking 的提示测试。模型是 4 位量化配置，实际运行设备为单张 **NVIDIA H200 NVL**，不是消费级显卡。

三个核心漏斗指标为：

1. **Found@24**：24 次探测是否已经接触至少一个正确实体。
2. **Top6@24**：缩到六个终选候选后是否仍包含正确实体。
3. **PW@1 / LW@1**：分别由逐点最高分或并排比较选出的一个实体是否正确。

词面困难集有 94 条，定义为最佳 gold 的 BM25 名次在第十名以后。图多跳组有 65 条，定义为 BM25 前五种子到目标的最短无向距离至少两跳。附录另报告按正向传播距离定义的 72 条多跳组。这些定义不能混写成“任务需要至少两步推理”。

主要对照各回答一个问题：

- **Flat BM25**：只按词面挑前 B 个，再用相同模型打分与终选，测量图探索的增量。
- **Static Dir-PPR**：先用有向个性化 PageRank 选候选，测量固定结构排序能否替代观察后的动态更新。
- **Undir-AST**：在新图的全部方向做对称正向传播，测量不区分方向的代价。
- **Fixed-Dir**：只沿主张有效的方向传播，但用固定的 `0.5×s/3` 权重，测量复杂校准是否真的必要。
- **Oct13-Undir**：使用竞赛旧图传播，检查原图质量的影响。
- **BAGEL-GP (Comp256)**：基于竞赛嵌入与高斯过程做主动搜索。由于这些嵌入仅有公开组，此对照只覆盖 113 条任务，属于特定资源条件下的实现，不能代表 BAGEL 所有配置。

另有五种单组件消融：用原始分数替换校准、取消关系门槛、反转方向、去掉度数衰减、去掉两跳通路。没有直接在本文协议中重跑完整 CoSIL、LocAgent 或 SWE-agent，因此结果不构成对这些完整智能体的排名。

## 十一、核心结果：困难任务的改善明显，整体改善很克制

### 11.1 最显眼的 23.4%，究竟与什么比较？

表 5 的 LW@1 是最终实体命中率，以下将总体与词面困难集分开：

| 模型 | 全体：BM25 → GraphScent | 困难 94 条：BM25 → GraphScent |
|---|---:|---:|
| E4B | 39.3% → 41.2% | 3.2% → 10.6% |
| 12B | 39.3% → 41.7% | 9.6% → 17.0% |
| 31B | 41.7% → 43.6% | 12.8% → 23.4% |

31B 困难组净增 10.6 个百分点，配对统计为 14 胜、4 负、76 平；2,000 次配对 bootstrap 的 95% 区间为 [+2.1,+19.1] 个百分点，p=0.015。12B 困难组虽然点估计提高 7.4 个百分点，区间为 [−1.1,+16.0]，未能排除零差异。

全部 211 条中，超过一半的任务本来就有 gold 位于 BM25 前十，因此总体提升只有约 1.9–2.4 个百分点。这篇论文最强的正向结果集中在词面难找的目标，不能把 12.8% → 23.4% 写成全任务或修复成功率翻倍。

### 11.2 看漏斗，能发现“探索成功、决策失败”

31B 的 Flat BM25 为：Found 69.2% → Top6 64.5% → LW 41.7%。GraphScent 为 74.9% → 68.7% → 43.6%。图搜索帮助一些目标进入已读集合，但后续仍丢失不少命中机会。

Undir-AST 的 Found 同样为 74.9%，最终 LW 却只有 41.7%。对于 E4B，Undir-AST 与 GraphScent 的 Found 都是 70.6%，最终却分别为 35.5% 与 41.2%。相同“找到过”不保证候选列表同样干净，也不保证终选一样容易。

在 31B 困难组，GraphScent 的 Top6 命中为 40.4%，Flat BM25 为 24.5%，最终分别变为 23.4% 与 12.8%。这把增益定位到候选发现、保留和选择之间的具体环节，远比只报一个最终分数更有解释力。

### 11.3 并排终选很有用，但增加了一次有信息的决策

GraphScent 从 PW 到 LW，E4B 为 28.9% → 41.2%，12B 为 29.9% → 41.7%，31B 为 36.0% → 43.6%，三组配对检验都支持正向差异。

这个发现说明单点四档分数不足以完成最后区分。与此同时，不能把全部增益归为“消除平分噪声”：并排调用看到了多个候选的关系与对比，还增加了一次调用。它检验的是加入这一终选步骤的总体价值，尚未隔离比较信息与额外预算各自的贡献。

## 十二、最值得认真保留的反例：完整方法并非每次最好

### 12.1 方向比复杂校准更稳定

反转传播方向后，E4B/12B/31B 的 Found 分别从 70.6/71.1/74.9 降到 64.0/69.2/72.0；困难组 LW 从 10.6/17.0/23.4 降到 3.2/7.4/14.9。这个消融支持当前任务与提示条件下的正向传播设计。

但与更简单的 Fixed-Dir 比较，情况不同。E4B 的完整方法为 41.2%，Fixed-Dir 为 37.4%；差值 +3.8 个百分点的区间是 [−0.9,+8.5]，p=0.126，不能称作统计上确定的改善。12B 的完整方法 41.7%，反而低于 Fixed-Dir 的 44.1%；31B 两者均为 43.6%。

31B 困难集上，完整方法 23.4% 高于 Fixed-Dir 的 20.2%，但 +3.2 个百分点区间为 [−4.3,+10.6]，p=0.475。校准对小模型过度自信的解释合理，证据强度仍应按对照分别陈述。

### 12.2 门槛、衰减和两跳，都没有被证明为普遍必要

31B 去掉硬门槛后，LW 从 43.6% 变为 44.5%，困难组从 23.4% 变为 24.5%。作者解释，校准后的弱关系本来就接近零权重，软加权可以容纳少量有用的覆盖关系，不一定需要硬删除。

去掉度数衰减后，E4B 总体从 41.2% 升到 42.2%；31B 困难组从 23.4% 升到 25.5%。去掉两跳后，31B 总体为 44.5%，无向多跳组达到 26.2%，也高于完整方法的 21.5%。这些点估计不自动代表简化方法稳胜，但足以否定“完整组件各自缺一不可”的叙事。

### 12.3 更多探测与更宽松指标，也会改变答案

预算从 15 次增至 24 次，GraphScent 的总体 LW 在 E4B/12B/31B 上分别为 38.9→41.2、40.8→41.7、42.7→43.6。预算作用存在，但幅度不大，其他方法也可能非单调。例如 31B Fixed-Dir 在 B=15 为 44.1%，B=24 为 43.6%。更多观察可能改变候选竞争，不能默认只会增加成功率。

附录还给出文件或包围作用域层面的宽松命中。31B 的 Flat BM25 宽松命中为 52.1%，GraphScent 为 48.3%，与严格实体命中的方向不同。这提示细粒度改进可能伴随目标选择范围的变化，不能把实体准确率优势直接迁移到文件级任务。

### 12.4 仓库异质性很强

在 rich 的 44 条任务上，12B GraphScent 为 29.5%，Flat BM25 为 40.9%，Fixed-Dir 为 47.7%；同一仓库换到 31B，GraphScent 为 50.0%，高于 BM25 的 40.9%。在 requests 的 12 条任务上，31B BAGEL-GP 为 66.7%，GraphScent 为 58.3%。

所以“两组仓库不重叠”增强了外推检查，但没有消除模型、仓库与方法的交互。只有一条任务的 httpx 全部方法命中，也不应被单独解读为强泛化证据。

## 十三、另外两条失败路线：补丁监督与更长思考

附录 E 报告的负面结果与本文目标直接相关。

作者用历史 issue 到补丁的标签，在 31B 上采用秩为 16 的低秩适配（Low-Rank Adaptation，LoRA）微调：编辑函数标为 3，未编辑函数标为 0。在 1,540 个公开组节点上，直接目标 AUROC 从 0.713 降到 0.704，一跳邻居的 AUROC 从 0.570 降到 0.536。

合理解释是，这种二分类式标签会把可带路的未编辑调用者一起压低。它说明“训练识别需修改代码”和“训练发现能引向修改目标的线索”可能冲突。但这不是对所有微调方案的否定，训练标签本身就是重要处理变量。

打开 thinking 后，直接目标 AUROC 从 0.713 提高到 0.731，一跳邻居几乎不变，0.570 → 0.567；受限输出下的 JSON 完成率从 100% 降为 96%，输出 token 延迟增加六倍以上。对于这个短输出内循环，作者选择关闭 thinking 有依据。它不能扩张成复杂最终机制推理也无需思考。

历史共同修改与竞赛嵌入的弱效果也被保留为负面结果。代码历史和语义向量提供了相关性，却没有在这里稳定带来更好的搜索导航。

## 十四、AST Ripple：修完一个地方后，提醒还有谁可能需要同步改动

图 1 右侧从另一个阶段提出问题。作者观察的 1,087 条 31B 单轨迹修复运行中，单文件补丁任务解决率为 39.1%，双文件为 18.6%，三文件及以上为 9.4%。多文件任务往往更难，这些分组也同时包含任务复杂度差异。

AST Ripple 在已有草稿补丁之后工作：解析修改涉及的函数或类签名，查询其他文件中尚未修改的直接调用者和平行覆盖方法，输出不超过 900 字符、约 160 token 的提醒。回到前面的演示，修改同步解析方法后，另一份异步实现可能值得检查。

作者对两次独立的 31B 补充集运行以及一个 248 条任务的 E4B 运行做回溯分析。在“修复未成功、参考补丁涉及多个文件、模型至少漏了一个参考文件”的条件子集中，两个 31B 运行都在 11/22 条任务中找回至少一个漏掉的参考文件，命中率 50%；E4B 为 21/71，即 29.6%。

另一个零样本裁决实验让模型区分 33 个漏掉的参考目标文件与 82 个未改邻居，AUROC 为 E4B 0.647、12B 0.659、31B 0.582。更大模型在这一小实验中没有更高分。

这些是**遗漏参考文件的候选提示能力**。论文没有将提醒真正接回智能体、再跑测试并与无提醒条件比较，所以不能声称它把失败修复挽救了一半，也不能把 50% 当成完整遗漏文件召回率。

## 十五、资源开销：小峰值上下文与小总成本要分开

附录 F 给出每任务 25 次无状态调用的开销：

| 模型 | 显存 | 单节点输入中位数 | 累计输入中位数 |
|---|---:|---:|---:|
| E4B | 10.42 GiB | 657 token | 18,886 token |
| 12B | 8.51 GiB | 669 token | 18,309 token |
| 31B | 20.28 GiB | 691 token | 15,211 token |

终选输入中位数约 2,050–2,197 token，输出每次限制 32 token，累计输出约 225 token。E4B 的显存大于 12B 是论文所报具体配置结果，不能按名称大小自行改成单调关系。

GraphScent 将会话历史移到外部状态，使单次提示保持较短，避免注意力键值（Key-Value，KV）缓存随阅读历史一直增长。这个优点针对峰值上下文与显存。其累计输入仍有一万多 token，且实际计时平台是 H200，因此“可在约 24GB 显存容量内放下”与“已在消费卡验证相同吞吐和时延”要分开。

## 十六、公开工件核验：哪些数字能复算，哪些还对不上？

本次精读除了读完整 v1，还检查了 Kaggle 公共发布的 **version 1**，没有调用语言模型重新跑实验。下载包中包含 Python 工具库、三份 JSONL、统计摘要、相图数据和 Notebook。以下是独立检查发布文件的结果，而非论文新增实验。

**第一，重要主结果可以从逐任务记录重算。** 活跃搜索文件共有 2,577 条“任务×模型×策略”结果，覆盖 211 个不同任务。自行汇总可以得到 31B GraphScent 的 43.60% 总体命中、23.40% 困难组命中，以及 Flat BM25 的 41.71% 与 12.77%，与论文四舍五入后吻合。方向诊断文件包含 4,701 条关系记录、14,103 个三模型评分；自行重算 parent、called_by、calls 与 sibling 的 AUROC 也与表 3 一致。

**第二，公开缓存没有覆盖正文宣称的完整策略范围。** 这份 JSONL 只有 Flat BM25、GraphScent、Undir-AST、旧图传播与 BAGEL-GP 五种策略，后三者中的旧图和 BAGEL 只覆盖公开组。未见完整单组件消融与 Static Dir-PPR、Fixed-Dir 的逐任务结果，不能仅凭该缓存重建论文全部 12 模式对照。

**第三，相图版本不一致。** 论文描述 12×12 配置、40 个任务图、5,760 次模拟；公开 `phase_diagram.json` 是 49 格，元信息为 211 个任务、5 个种子。它不直接对应论文图 4(a) 所述实验设计。

**第四，公开搜索实现与公式没有完全对齐。** 论文写逐次累加 LLR、按关系度衰减并用邻居访问计数奖励；发布的 `search.py` 则包含按关系取最大传入证据、将负证据折半、区分已读与未读节点的不同信念组合、默认批量选三个、以及另一种扩展奖励。公开实现的两跳规则也与附录叙述不同。它们可能属于不同开发版本，目前不能直接认定这份库就是生成论文全部表格的冻结实现。

因此，对工件最准确的评价是：**主结果的一部分具有可检查的逐任务支持，完整方法与全部消融的端到端复现仍需版本对齐。** 缓存分析 Notebook 快速重绘统计，与独立重跑 46,032 次模型评估，是两个层次。现有不一致不构成造假结论，也不应被“全开源、可十秒复现”一句话掩盖。

## 十七、证据审查：方向信号成立，还不等于发现了普适因果规律

### 17.1 提示词已经包含方向性偏好

四档评分的 2 分明确写入了“直接调用者”和“包含作用域”。论文没有给出移除这些方向术语、只保留中性任务相关量表的对照。因此观测到的差异是**这套提示量表、折叠视图和 Gemma 4 的联合表现**，不能全部归为模型自然发现的结构规律。

这不取消方法价值：工程上可以设计有用量表。它改变的是机制主张的强度。若要说明方向性独立于提示成立，应加中性量表、关系盲化或提示改写的配对控制。

### 17.2 离线 oracle 只用于研究时，必须保持边界

邻居采样、far 距离筛选、gold 方法遮挡与困难任务分组，都使用参考目标，适合离线测量。部署控制器应只接收外部校准表、issue、仓库图和实际读到的代码。

另外，“距目标三跳以上且未被修改”只是对照项的操作定义，未经过人工机制审查，不能保证完全不相关。补丁未改位置也可能是理解任务所需的支持代码。这里的 far 与 CPI 的 I 不是同义词。

### 17.3 重叠控制和回归缩小了解释空间，没有穷尽混杂

遮掉 gold 方法体排除了直接源码重叠，词面与长度控制排除了两个简单解释。但函数职责、文档质量、接口层级、具体缺陷类型及量表本身都可能参与形成差异。方向反转消融检验的是搜索控制器改变后的结果，也同时改变了候选分布。

加法 LLR 还可能重复累计相关邻居的证据。多个调用者共享同一条线索时，它们未必相互独立；“belief”在这里适合作为排序状态，不应未经验证就当作严格校准的后验概率。

### 17.4 方法有效性存在明显异质性

只有一个模型家族、三种规模、Python 实体、最多 60 行视图与固定量表。校准公开组只有四个仓库；按任务 bootstrap 处理了同任务节点的依赖，却不完全解决仓库层面的聚类。部分关键消融差异的区间跨零，且没有展示所有组件在独立新任务上的选择过程。

例如门槛和两跳并非稳定有利，12B 在 rich 上退化明显，严格与宽松指标也可能反向。更合理的结论是“某些方向性证据对这些设置有效”，而非找到一套固定图传播最优配置。

### 17.5 基准、修复和真实部署仍有距离

实体映射排除了 20 个任务，公开组被两个仓库主导，补充时间段无法保证未被模型训练见过。公开与补充集相互独立，也不等于它们与我们当前任务集独立；后续若借用数据，还要核对仓库、issue/修复提交和 base version。

没有与完整图定位智能体做同期同协议重跑，AST Ripple 也没有闭环修复增益证据。资源实验证明了具体配置的显存占用，尚未证明消费卡上的真实运行时体验。

## 十八、先总结论文本身，再讨论如何借用

这篇论文最值得记住的四点是：

1. **“相关”可以有导航价值，即使它不是修改目标。** 在指定量表下，父作用域和上游调用者的分数，比下游工具与同级方法更能区分结构邻近目标。
2. **原始高分不等于强证据。** E4B 大量给干扰项打 3 分，关系条件校准能把这种过度自信折算为更温和的更新。
3. **搜索与决策要分别评价。** 找到过目标、保留进短名单、最终选对，三者之间都有明显损失；一次并排终选的价值值得独立衡量。
4. **最强收益集中在词面困难任务，组件价值有条件。** 总体提升温和，复杂校准、硬门槛、衰减和两跳没有共同组成一个处处最优的组合。

作者没有证明每个高 scent 邻居都因果必要，没有证明图方向提示适用于所有模型，也没有证明 AST Ripple 改善最终修复。它提供了一个很有研究价值的测量与设计范例，而非可直接套用的普适法则。

## 十九、对当前 CPI 与图定位研究的具体启发

### 19.1 把“可带路线索”和“最终决定性证据”分开

GraphScent 最接近我们的地方，是承认未修改的邻居也可能有导航价值。人工 C/P/I、部署时暂定候选状态、本文的 0–3 分，以及结构关系 r，是四种不同对象。

一个节点可能很适合引导搜索，却不应该成为最终修改位置；另一个节点可能是竞争解释，但其反证有助于排除错误路线。不能用是否出现在补丁里，直接教选择器把全部未编辑节点当成 I。这一点与论文的补丁 LoRA 负面结果相互呼应。

### 19.2 等曝光下的方向效应，适合做配对诊断

对既有 CoSIL、LocAgent、SweRank 输出，首先固定底层任务和真实曝光，再分析：上游调用者、下游被调用者、包含作用域、同级节点分别被看见、保留、压缩或排除了多少；最终错误发生在未曝光、筛掉还是保留后误判。

若要进一步检验方向的机制价值，可以在同一任务的相同候选池中，对中性量表与带方向提示量表、等 token 的 caller/callee 支持材料、保留与压缩条件做配对比较。gold 仅用于离线分层和评分，不应混入部署选择器输入。

这是一条可检验的设计建议，不是现有实验已经得出的结论。

### 19.3 不要用“几乎没删节点”代替有效处理，也不要只追求删得更多

论文显示，点分数、短名单与最终选择之间存在损失。我们的筛选裁决也应记录完整链条：来源方法曝光了什么，筛选真的改变了什么，关键目标和支持材料是否保留，最终是否更好。

若输入几乎不变，额外分类调用可能只增加成本；若输入减少很多，仍可能误删支持证据。可恢复索引或短证据保留值得作为独立方案比较，不能仅因理论上合理就当成性能升级。

### 19.4 当前 38 个独立任务要守住同一实验单位

重复组按冻结顺序选第一个，让方法比较以同一底层任务为单位。GraphScent 的 211 条实体定位与当前任务的信息条件、粒度和评价指标不同，数值不可横向拼表；其公开集和补充集内部不重叠，也不代表与我们的任务无重叠。

适合直接借用的是漏斗式日志、模型分数校准检查、方向性配对对照，以及 token 总量与峰值上下文分开报告的方法。至于是否将整套控制器加入当前路线，应先对齐公开代码与论文版本，再在冻结任务上检验，避免用一个新的复杂组件替代尚未完成的基础比较。
