## 先讲一个容易混淆的失败：检索到了相关材料，模型为什么仍会答错？

假设问题是：“404 Page Not Found 这个名字源自哪个著名实验室的一间房间？”检索器返回两种可能的材料：

- 材料 A 解释 404 表示服务器找不到页面，并列出 URL 拼写错误、页面迁移等原因；
- 材料 B 明确说 404 这个编号源自 CERN 的 Room 404，那里曾保存错误消息数据库。

两份材料都和 404 高度相关，但只有材料 B 足以回答问题。若模型读到 A 后回答“CERN”，答案可能碰巧正确，也可能来自预训练记忆；若它答错，也不能立刻归咎于模型不会利用检索结果，因为检索结果本来就没给出答案。

这就是论文要解决的基本混淆：

1. **检索失败**：上下文本身缺少回答所需信息；
2. **利用失败**：信息已经在上下文里，模型却没能组合或使用；
3. **拒答失败**：信息不足时，模型仍自信地给出答案。

传统 RAG 评估通常只看最终答案是否正确，或者把文档分为“相关/不相关”。这两种做法都无法把上述三种失败拆开。本文的核心贡献，是把“当前问题—上下文对是否已经足够”定义成一个独立、可标注的变量，再用它重新分层观察模型行为。

这篇论文发表于 ICLR 2025。发表渠道能说明其问题具有较高的机器学习研究关注度，但不能替代对定义、标注与实验的审查。

对当前仓库上下文研究，这篇论文的价值尤其直接。我们现在不仅要判断 P 是否让最终节点 F1 下降，还要区分：原 Core 是否已经足以回答漏洞机制问题，P 是否补入了新的可达性或规格事实，以及模型是否在证据足够时仍选择了错误对象。本文提供了“先标输入是否足够，再评价模型是否用好”的基本分解，也提醒我们：**上下文不充分仍可能对答案有增量帮助，模型答对也不等于上下文充分。**

## 论文的基本思路：先评价信息条件，再评价模型答案

论文把一次问答写成 `(Q, C; A)`：

- `Q` 是问题；
- `C` 是检索到的上下文，由若干事实组成；
- `A` 是数据集给出的标准答案。

模型实际推理时通常只看到 `(Q, C)`，再结合参数记忆生成 `A'`。作者先不看模型回答，也不依赖标准答案，单独问：

> 仅根据 Q 和 C，是否存在一个由 C 支持、能够明确回答 Q 的合理答案？

若存在，作者把这对输入标为 **Sufficient Context**；否则标为 **Insufficient Context**。

这一定义有三个重要细节。

### 1. 充分性属于“问题—上下文对”，不是文档的固定属性

同一段代码或文档，对问题 Q1 可能充分，对问题 Q2 可能只是在主题上相关。不能脱离问题给一个片段永久贴上“充分”标签。

### 2. 充分性与蕴含标准答案不同

传统 entailment 问的是：“给定标准答案 A，C 是否支持 A？”充分上下文问的是：“不给 A，C 中是否存在一个可构造的明确答案？”

若数据集标准答案有误，C 仍可能足以支持另一个合理答案。这时“C 不蕴含 A”不代表 C 不充分。反过来，若 C 中出现答案字符串，却没有足够信息确认实体或关系，也不能仅靠字符串出现认定充分。

### 3. 相关、帮助与充分是三种不同属性

材料 A 关于 404 的网页错误解释很相关，却不充分。另一段材料可能只消除问题中的实体歧义，仍不能独立给出答案；它也不充分，但可能让模型结合参数知识后答对。因此：

| 属性 | 它真正问什么 |
|---|---|
| 相关性 | 内容是否与问题主题有关？ |
| 增量帮助 | 加入内容后，模型是否更容易答对？ |
| 充分性 | 当前上下文本身是否包含构造明确答案所需的全部信息？ |

本文后续实验最有价值的地方，就是没有把这三个概念合成一个“检索质量”。

## 第一步：怎样自动判断上下文是否充分？

作者首先构建一份小而难的人工金标集，用于验证 AutoRater 是否可信。

### 人工标注集

金标集包含 115 个 `(问题, 上下文)` 实例，来自 PopQA、FreshQA、Natural Questions 和 EntityQuestions。标注时不使用标准答案，也不看被评模型的回答，只依据充分性定义判断上下文是否已经足够。

作者有意加入困难实例：

- 单跳与多跳问题混合；
- 上下文中经常出现问题里的实体名称；
- 即使不充分，也提供高度相关的信息；
- 某些上下文存在歧义、不完整事实或相互冲突的线索。

这样可以避免 AutoRater 只学会“看到同名实体就判充分”。

### 比较的五种判断方法

作者比较两个不需要标准答案的方法和两个需要标准答案的基线：

| 方法 | 是否需要标准答案 | F1 | Accuracy | Precision | Recall |
|---|---:|---:|---:|---:|---:|
| Gemini 1.5 Pro，1-shot | 否 | 0.935 | 0.930 | 0.935 | 0.935 |
| Gemini 1.5 Pro，0-shot | 否 | 0.878 | 0.870 | 0.885 | 0.871 |
| FLAMe 24B | 否 | 0.892 | 0.878 | 0.853 | 0.935 |
| TRUE-NLI | 是 | 0.818 | 0.826 | 0.938 | 0.726 |
| Contains GT | 是 | 0.810 | 0.809 | 0.870 | 0.758 |

这里最值得读的是 precision 与 recall 的差异。TRUE-NLI 只判断上下文是否蕴含给定标准答案，因此 precision 很高，recall 较低；上下文可能足以导出一个合理答案，却不支持数据集给的那个 A。Gemini 1.5 Pro 的 1-shot 版本在无需标准答案的情况下达到 93% accuracy，作者因此用它给后续大规模数据打充分性标签。

FLAMe 的上下文窗口较小。作者把上下文切成 1600-token 块，只要任一块被判充分，整个实例就判充分。这种实现高效，却带来一个边界：若答案必须跨块组合，逐块判断可能把本来充分的上下文误判为不充分。

### 这一阶段证明了什么？

它证明一个强模型可以较准确地近似人工充分性标注，足以支持后续分层分析。它没有证明 AutoRater 是无误差的金标准，也没有证明 115 例覆盖所有领域。93% accuracy 仍意味着标签误差会进入后续结论，尤其在边界实例上。

## 第二步：常见 RAG 数据集真的给了充分上下文吗？

作者分析三套数据：

- **FreshQA**：452 个 True Premise 问题，使用数据集提供的时效性网页 URL 构造上下文；
- **Musique-Ans**：从开发集采样 500 例，每例提供 20 个支持文本片段，问题需要 2–4 跳组合；
- **HotpotQA**：从开发集采样 500 例，在 Wiki-18 语料上用 E5 dense retriever 检索 top-5 文档。

作者没有尝试把检索器调到最强，因为研究目标是分析“充分与不充分条件下模型怎样表现”，而不是刷新 RAG 分数。

### Figure 2：更多 token 是否自然带来更多充分上下文？

Figure 2 的横向比较是三个数据集，纵向指标是被 AutoRater 判为充分的实例比例；每个数据集分别看前 2k、6k、10k token。

结果显示，从 2k 增加到 6k 有温和提升，从 6k 增加到 10k 几乎没有变化。FreshQA 的充分比例最高，因为它使用人工维护的支持 URL；Musique 即使名义上是 answerable 子集，仍有大量实例的给定片段不够充分。作者随后统一使用 6000-token 上下文。

这说明“上下文更长”不能自动等价为“证据更完整”。如果新增部分只是重复、同主题材料或缺少关键一跳，长度增加不会修复信息缺口。

## 第三步：按充分性分层后，模型的错误来自哪里？

作者测试 Gemini 1.5 Pro、GPT-4o、Claude 3.5 Sonnet、Gemma 2 27B 等模型。提示要求模型仅根据搜索结果作答，并允许回答 “I don’t know”。模型输出被分成三类：

- Correct：答案正确；
- Abstain：拒答或没有给出答案；
- Hallucinate：给出了错误答案。

自由文本答案使用 LLM evaluator 判断语义等价性。附录同时比较简单字符串匹配，主要趋势一致。LLM Judge 能识别 “13 August 1896” 与 “August 13, 1896”、正式姓名与常用名等语义等价情况，也能避免只因答案短语出现在一段错误解释中就判对；代价是评分仍存在模型偏差。

### Figure 3 应怎样读？

Figure 3 按数据集和模型画 Correct、Hallucination、Abstention 三段比例，并把每个数据集再分为充分上下文与不充分上下文。

读图顺序应是：

1. 先比较充分与不充分两行的绿色 Correct 比例；
2. 再看错误质量，是蓝色拒答增加，还是红色幻觉增加；
3. 最后比较不同模型，而不能只看总体 accuracy。

作者得到四个关键发现。

### 发现一：上下文充分时，模型仍会答错

充分上下文组的正确率显著更高，但并未接近 100%。附录的人标子集显示，充分上下文占 54.8% 时，强模型仍有约 14%–16% 的错误。这些错误不能再由“检索没给信息”解释；多跳组合、算术、实体消歧或模型没有正确利用证据，都可能导致失败。

因此，提升检索充分率仍无法单独解决开放式问答。它只能减少一种失败来源。

### 发现二：上下文不充分时，模型经常幻觉而不拒答

不充分组中，模型的拒答会增加，但错误作答仍然很多；附录人标子集中的幻觉率约 15%–40%。较小模型 Gemma 27B 尤其容易产生幻觉。

这说明“允许模型说不知道”不等于模型能可靠识别信息缺口。是否拥有足够证据与是否愿意拒答，是两个独立能力。

### 发现三：加入 RAG 反而可能降低拒答率

在论文报告的总体比较中，Claude 3.5 Sonnet 的拒答率从无 RAG 的 84.1% 降到有 RAG 的 52%；GPT-4o 从 34.4% 降到 31.2%；Gemini 1.5 Pro 从 100% 大幅降到 18.6%。

作者推测，只要出现检索材料，模型就可能提高主观信心，即使材料并不充分。这个解释是对行为的合理推断，论文没有通过直接操纵“材料存在感”或测量内部置信机制来证明因果路径。

### 发现四：不充分上下文下，模型仍有 35%–62% 的正确回答

这看起来反直觉。若上下文不充分，为什么还会答对？作者在 Table 2 中人工归纳出八类原因：

| 类型 | 答对的可能原因 |
|---|---|
| Yes/No | 即使缺证据也有约一半猜中机会 |
| Limited choice | 选项有限，猜中概率不低 |
| Multi-hop fragment | 上下文提供一部分桥梁，模型用参数知识补齐 |
| Multi-hop partial | 缺失一跳，但模型恰好记得缺失事实 |
| Too many hops | 事实都在，却需要复杂组合，AutoRater 可能判断保守 |
| Ambiguous query | 模型猜中了问题的预期解释 |
| Rater error | 充分性或答案评分器判断错误 |
| Closed-book correct | 模型本来就从预训练中知道答案 |

这张表对“P 是否有信息”的研究特别重要。一个片段可能不足以独立回答，却能补一座桥、消除歧义或提醒模型调用已有知识。把它标为 insufficient，不能推导出它“没有增量价值”。

同样，模型答对也不能反推输入充分。它可能靠参数记忆、猜测或答案空间很小而成功。

## 第四步：怎样利用充分性信号减少幻觉？

最简单的策略是：AutoRater 判不充分就拒答。作者没有采用这一硬门槛，因为模型在不充分组仍能答对相当多问题，全部拒答会损失 coverage。

### 选择性生成：同时看“信息够不够”和“模型有没有把握”

作者组合两个信号：

1. **Sufficient-context label**：FLAMe 判断当前上下文是否充分；
2. **Self-rated confidence**：开源模型使用 P(True)，闭源模型使用 P(Correct)。

P(True) 的成本很高：每题采样 20 个回答，再查询模型 5 次判断答案真伪。P(Correct) 则要求模型输出最可能答案、次可能答案及各自概率。

作者把充分性二值标签和自评置信度输入一个简单 logistic regression，预测当前回答是否会幻觉。推理时用阈值决定回答或拒答。

这里的两个指标是：

- **Coverage**：系统实际回答的问题比例；
- **Selective Accuracy**：在系统选择回答的那些问题中，正确答案所占比例。

阈值越严格，coverage 通常越低，留下的问题越容易答对，selective accuracy 越高。

### Figure 4：充分性信号是否比模型自信更有用？

Figure 4 横轴是 coverage，纵轴是 selective accuracy。灰线只用模型自评置信度，紫线同时使用置信度和充分性。

组合方法总体持平或更优：Gemma 27B 在 HotpotQA 的高准确率区域提升超过 10 个百分点，Gemini 1.5 Pro 在约 70% coverage 附近提升超过 5 个百分点。论文总体总结为，Gemini、GPT 和 Gemma 的回答子集准确率提升约 2%–10%。

但该信号不是处处有效。Gemma 27B 在 Musique 上总体准确率只有 18.4%，回归模型把充分性系数学成 0，组合方法与只用置信度完全相同。作者据此指出：充分性信号发挥作用的前提，是基础模型在充分与不充分组中都具备非平凡的正确率。

### 证据边界

这项实验表明充分性标签对“何时回答”有额外预测价值。它没有表明 AutoRater 修复了生成模型的推理，也没有说明充分性是幻觉的唯一原因。logistic regression 只是外部选择器，把高风险回答过滤掉。

## 第五步：直接微调模型学会“不知道”，为什么没成功？

作者还尝试了更直接的办法：用 LoRA 微调 Llama 3.1 8B 和 Mistral 3 7B，让模型在证据不足时输出 “I don’t know”。

每个数据集采样 2000 个训练实例，构造三种训练混合：

1. **Data Mix 1**：所有实例保留标准答案；
2. **Data Mix 2**：随机把 20% 的答案改为 “I don’t know”；
3. **Data Mix 3**：把 AutoRater 判为不充分的 20% 实例改为 “I don’t know”。

直觉假设是，Mix 3 应该最能教会模型在证据不足时拒答。结果没有支持这个假设。

在 Musique 上，Llama 的 Vanilla RAG 为 19.6% correct、53.6% abstain、26.8% hallucinate；Mix 3 变为 25.0% correct、38.8% abstain、36.2% hallucinate。正确率略升，但幻觉也升高，拒答反而比 Vanilla RAG 少。

Mistral 的情况更明显：Musique 上 Vanilla RAG 幻觉率为 59.4%，Mix 3 升到 74.8%，拒答只有 2.2%。四个模型—数据集组合中，微调在三个组合提高了正确率，但所有 RAG 微调版本仍至少约 31% 幻觉，并且经常比拒答更多。

作者原假设“把不充分样本标成不知道，会比随机 idk 更能改善拒答”没有得到支持。这个负面结果说明，训练标签里加入拒答示例会改变整体回答倾向，却不保证模型学会了可泛化的证据充分性判断。外部选择器反而更可控，因为它不改写生成模型本身。

## 这篇论文真正证明了什么？

论文的证据支持以下判断：

1. 问题—上下文充分性可以独立于标准答案和模型回答进行定义，并由强 AutoRater 较准确地近似人工标注；
2. 常用 answerable 数据集和 oracle-like 来源中仍可能存在大量信息不充分实例；
3. 上下文充分能显著提高正确率，却无法保证模型正确利用证据；
4. 上下文不充分时，模型仍可能靠参数知识、猜测或局部桥接答对，因此“答对”与“充分”不能互相替代；
5. 充分性信号与模型置信度结合，可以改善部分模型和数据集的 accuracy–coverage 权衡；
6. 简单地用不充分标签构造 “I don’t know” 微调数据，并没有可靠地教会模型拒答。

论文没有证明：

- 充分性 AutoRater 能无修改迁移到代码、安全或长仓库场景；
- 被判不充分的上下文没有增量信息；
- 任意检索器增加上下文都会降低拒答或提高幻觉；
- 只要上下文充分，剩余错误就一定是模型推理缺陷；标签、问题歧义和 Judge 仍可能出错；
- 充分性标签可以替代最终任务指标。

## 方法上的限制与构念风险

### 1. 定义中的“plausible answer”比事实正确更弱

充分性要求存在一个由上下文支持的合理答案，却不要求它与数据集标准答案一致。这有助于发现错误 GT，也意味着充分性标签不能直接充当 correctness 标签。

### 2. AutoRater 与答案 Judge 都是模型

作者用人工集校准 AutoRater，并用字符串匹配验证主要趋势，但后续大规模分层仍依赖模型标注。两个 Judge 的错误可能相关，尤其在多跳、歧义和长上下文条件下。

### 3. 数据范围主要是开放域 QA

代码定位需要判断危险操作、触发条件、可达性与修复边界，答案往往不是一个实体短语。论文明确承认其分析集中于 QA；迁移到代码时必须重新定义“明确答案”和“必要信息”。

### 4. 充分性是整体二值标签，无法说明哪一块证据必要

若 C 被判充分，我们仍不知道是哪些片段共同使它充分，也不知道某段新增材料是重复、桥接还是干扰。要做细粒度归因，还需要片段消融或证据角色标注。

### 5. 选择性生成提高的是回答子集准确率

系统通过多拒答减少错误，不等同于总体任务能力提升。报告时必须同时给 coverage 和 selective accuracy，不能只报后者。

## 对当前 Plausible Context 研究的直接迁移

这篇论文最有价值的迁移不是照搬一个 AutoRater prompt，而是建立三层互不替代的测量。

### 第一层：Context Sufficiency，输入客观上够不够？

对每个漏洞实例，先冻结与任务相关的问题，例如：

- 哪个具体操作产生风险？
- 风险需要什么输入或状态触发？
- 当前可见代码是否展示了关键缺失检查？
- 危险数据是否能从可见入口到达该操作？
- 两个相似候选中，哪个拥有本次题面要求的完整机制证据？

然后由人工依据仓库、补丁、测试和漏洞说明，给每题建立参考答案、必要证据集合与可接受的 `INSUFFICIENT_EVIDENCE` 条件。正式答题模型不能看到补丁或 GT。

注意：论文的充分性判定不依赖标准答案，适合真实部署；我们做研究评测时已有 GT 和补丁，可以用它们校验问题与必要证据，但不能让答题模型看到这些特权信息。

### 第二层：Incremental Utility，P 是否补入了新信息？

对同一冻结问题，比较：

- Core；
- Core + P；
- Core + I；
- Oracle evidence。

若 Core 与 Core+P 都答对，只能说未观察到 P 的答题增益，不能说 P 没有新事实。若 Core 错、Core+P 对，P 可能提供桥接证据，也可能只是触发模型记忆；还需检查模型引用的具体代码是否真实支持答案。

因此应像 Table 2 那样，为“不充分但有帮助”建立类型：

- mechanism bridge：补入一段漏洞机制链；
- reachability bridge：补入入口或数据流；
- ambiguity resolver：区分两个相似对象；
- specification cue：测试、文档或调用方式提示正确规格；
- parametric trigger：片段本身不够，但触发模型已有知识；
- guess / rater error：表观答对没有可靠证据。

这比把所有非 Core 内容都称作“无额外信息”更符合当前 580、HY、Pinot 与 go-proxyproto 的观察。

### 第三层：Decision Effect，理解变化是否进入最终定位？

Probe 答对不保证最终选对节点；定位 F1 下降也不证明模型不理解机制。应把每次运行拆成：

1. 当前上下文对冻结问题是否充分；
2. 模型回答是否正确并引用了真实证据；
3. 最终选择了哪些节点；
4. 错误来自漏证据、证据利用失败、新候选竞争，还是输出格式/基础设施失败。

这与最新的成功/失败轨迹相减可以自然结合。轨迹差集先产生候选差异，再依次审查：它是否增加必要事实，是否只增加可选身份，是否改变 Probe 回答，是否改变最终节点。只有当“信息条件不变而选择改变”时，才更接近候选竞争；当差集补入必要事实时，它属于信息增量，不能再当纯干扰。

### 建议的最小 Pilot

先选 6–8 个机制清楚、证据可人工核验的实例，覆盖：

- Core 已充分且结果稳定；
- P 救回定位；
- P 引入误报；
- P 使原 GT 漏报；
- 片段缺失检查；
- 完整相似机制竞争。

每例冻结 3–5 道题，至少包含机制、可达性和候选消歧。主分析使用人工参考答案与源码引用审核，LLM Judge 只做辅助；同一问题在所有实验臂保持完全一致。先确认题目能区分信息不足与模型不会用，再扩大到全部成功轨迹。

## 一句话抓住全文

这篇论文最重要的结论是：

> **先判断输入是否已经包含完成任务所需的信息，再评价模型是否答对，才能把检索缺失、证据利用失败和拒答失败分开。**

但“充分”不是“有帮助”的同义词。上下文可能不够独立回答，却提供关键桥梁；模型也可能在证据不足时凭参数记忆或猜测答对。对当前研究而言，P 的价值与伤害需要沿着“输入包含什么 → 模型理解了什么 → 最终选择了什么”三层证据链来测量，不能仅由节点 F1 或人工相关性标签反推。
